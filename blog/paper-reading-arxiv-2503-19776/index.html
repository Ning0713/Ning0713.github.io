    幻觉翻译 2503.19776

    恶劣传感器故障下基于多模态专家的鲁棒传感器融合（CVPR'25）

    本文提出 MoME（Multi-Modal Expert Fusion），以三条共享权重的 Camera、LiDAR 与 LiDAR-Camera 专家解码路径解耦模态依赖，再由Adaptive Query Router（AQR）根据 query 附近的局部特征进行硬路由。两阶段训练使用样本级传感器状态标签监督路由，在 nuScenes-R 多种传感器失效和 nuScenes-C 极端天气下提升鲁棒性；完整模型相对 CMT 的推理延迟仅增加 4ms。

    恶劣传感器故障下基于多模态专家的鲁棒传感器融合 CVPR’25 (CCF-A)

    开源代码：MoME

    1. 研究背景与动机#

    (1) 要解决什么问题？ 现代自动驾驶感知用 LiDAR 和相机进行多模态互补。融合架构在理想条件下效果较好，但在严重传感器失效下性能暴跌。根因是模态间依赖（inter-modality dependencies）：一个模态被污染会拖垮整体多模态感知质量。

    (2) 什么是模态间依赖？ 现有融合方法大多把两模态特征耦合在一起，如 BEVFusion 的逐元素相加、TransFusion 的互相 query。这种耦合意味着：camera 损坏或者 LiDAR 损坏都会污染共享特征。这种依赖在需要高层交互的融合中很难避免。

    (3) 现有方法的不足 MetaBEV、UniBEV、CMT、RobBEV 等虽缓解了传感器失效影响，但两模态特征仍耦合，性能下降不可避免。融合性能甚至常不如一个完好的单模态传感器。

    MoME 的核心思想 受 NLP 中 Mixture of Experts (MoE) 启发，提出 Multi-Expert Decoding (MED) 框架：用三个并行 Transformer 解码器（专家解码器）分别用 camera 特征、LiDAR 特征、或两者组合来解码共享的 object queries。这样彻底解耦模态依赖，保护检测器不受单模态失效影响。

    与“并行三解码器加置信度选最大”方案的区别

    朴素方案让三解码器并行处理所有 query，再按置信度选输出。有两个问题：

    1. 置信度未校准（uncalibrated confidence scores）：解码器独立训练，置信度不可比，选错；
    2. 解码复杂度×3：计算负担重。

    MoME 用 Adaptive Query Router (AQR) 为每个 query 选一个最合适的专家，既解决校准问题，又把复杂度压回接近单解码器水平。

    2. 核心贡献#

    1. 提出对传感器失效有韧性的 LiDAR-camera 融合架构 MoME，用三条共享 decoder 权重的模态专家执行路径（camera/LiDAR/LiDAR-camera）降低模态间依赖。
    2. 提出 MED 框架：为每个 query 选一条专家路径；设计 AQR 从 query 附近的局部多模态特征产生专家选择概率。
    3. 多专家解码器结构简单，易集成进任何 Transformer-based 特征融合架构；每个 query 只分给一个专家，计算开销最小，并且在多数传感器失效场景和多种极端天气条件下取得有竞争力或 SOTA 的结果。

    3. 方法详解#

    3.1 整体架构#

    3.2 Multi-Expert Decoding (MED)#

    AQR 处理每个 query qiq_iqi​ 和多模态特征 Fl′cF'_lcFl′​c，产生模态选择概率 pi=[pi,l,pi,c,pi,lc]p_i = [p_{i,l}, p_{i,c}, p_{i,lc}]pi​=[pi,l​,pi,c​,pi,lc​]。选概率最大的专家：

    Qmod={qi∈Q∣arg⁡max⁡(pi)=mod},mod∈{l,c,lc}Q_{mod} = \{q_i \in Q \mid \arg\max(p_i) = mod\}, \quad mod \in \{l, c, lc\}Qmod​={qi​∈Q∣argmax(pi​)=mod},mod∈{l,c,lc}

    3.3 Adaptive Query Router (AQR)（核心创新）#

    AQR 使用局部性感知自适应路由（locality-aware adaptive routing），为每个 object query 选择 LiDAR、Camera 或 LiDAR-Camera 三条专家路径中的一条。它解决当前 query 应该交给哪一种模态组合来解码。

    object query + 该 query 的 3D 参考点
                 ↓
将参考点投影到 LiDAR BEV 和 Camera 特征图
                 ↓
Local Attention Mask 只保留参考点附近的两模态特征
                 ↓
masked cross-attention + Linear + Softmax
                 ↓
得到 [LiDAR, Camera, LiDAR-Camera] 三种专家的选择概率
                 ↓
argmax 硬选择一个专家，再由该专家完成真正的目标解码

    因此需要把两个模块区分开：

    模块读取什么输出什么作用
    AQRquery 附近的局部 Camera/LiDAR 特征三个专家的选择概率判断走哪条路径
    Expert Decoder被选路径所对应的 Camera、LiDAR 或双模态特征更新后的 object query完成目标特征解码

    3.3.2 参考点怎样投影到两种模态#

    Local Attention Mask 的关键，是先确定“这个 query 附近”在两种特征域中分别位于哪里。AQR 对同一个三维参考点做两次映射。

    LiDAR 特征已经位于 BEV 网格中，因此只需把真实世界坐标 (xi,yi)(x_i,y_i)(xi​,yi​) 转成 BEV 的行列索引。一般可写成：

    ui(l)=⌊xi−xmin⁡xmax⁡−xmin⁡Wl⌋,vi(l)=⌊yi−ymin⁡ymax⁡−ymin⁡Hl⌋.u_i^{(l)}=\left\lfloor \frac{x_i-x_{\min}}{x_{\max}-x_{\min}}W_l \right\rfloor, \qquad v_i^{(l)}=\left\lfloor \frac{y_i-y_{\min}}{y_{\max}-y_{\min}}H_l \right\rfloor.ui(l)​=⌊xmax​−xmin​xi​−xmin​​Wl​⌋,vi(l)​=⌊ymax​−ymin​yi​−ymin​​Hl​⌋.

    于是 LiDAR 域中的参考位置为：

    pi,ref(l)=(ui(l),vi(l))T.\mathbf p_{i,\mathrm{ref}}^{(l)}= \left(u_i^{(l)},v_i^{(l)}\right)^{\mathsf T}.pi,ref(l)​=(ui(l)​,vi(l)​)T.

    3.3.3 Local Attention Mask 怎样构造#

    对于第 iii 个 query，先分别在两个域中构造局部允许集合：

    Limited FOV 下的具体路由例子

    假设第 iii 个 query 的参考点位于车辆右前方，而该区域恰好落在 Limited FOV 后 LiDAR 没有覆盖的角度内，但在右前相机中仍然可见。下面的坐标和 logits 仅用于说明计算过程。

    1. 参考点投影到 LiDAR BEV 的第 (134,52)(134,52)(134,52) 个网格，并投影到右前相机特征图的第 (18,67)(18,67)(18,67) 个位置。
    2. AQR 保留 LiDAR 侧以 (134,52)(134,52)(134,52) 为中心的 5×55\times55×5 token，以及 Camera 侧以 (18,67)(18,67)(18,67) 为中心的 15×1515\times1515×15 token。
    3. LiDAR 局部窗口内因为视场缺失，特征很弱或接近空；Camera 局部窗口仍含有车辆轮廓和纹理。
    4. masked cross-attention 聚合这些局部证据后，假设得到如下三个 logits：
    zi=[−1.22.40.3],\mathbf z_i= \begin{bmatrix} -1.2 & 2.4 & 0.3 \end{bmatrix},zi​=[−1.2​2.4​0.3​],

    其顺序为 LiDAR、Camera、LiDAR-Camera。Softmax 计算为：

    πi=1e−1.2+e2.4+e0.3[e−1.2e2.4e0.3]≈[0.0240.8700.106].\boldsymbol{\pi}_i= \frac{1}{e^{-1.2}+e^{2.4}+e^{0.3}} \begin{bmatrix} e^{-1.2} & e^{2.4} & e^{0.3} \end{bmatrix} \approx \begin{bmatrix} 0.024 & 0.870 & 0.106 \end{bmatrix}.πi​=e−1.2+e2.4+e0.31​[e−1.2​e2.4​e0.3​]≈[0.024​0.870​0.106​].

    因此：

    ei=arg⁡max⁡(0.024,0.870,0.106)=c,e_i=\arg\max(0.024,0.870,0.106)=c,ei​=argmax(0.024,0.870,0.106)=c,

    该 query 被送入 Camera Expert，后续不再读取损坏区域的 LiDAR 特征。与此同时，另一个位于 LiDAR 有效视场内的 query 可能选择 LiDAR-Camera Expert。也就是说，MoME 可以在同一帧中让不同空间位置的 queries 走不同路径，而不必把整帧统一切换成 Camera-only。

    3.3.5 AQR 是怎样学会“判断质量”的#

    论文所说的“based on the quality of camera and LiDAR features”容易被理解为 AQR 有显式的清晰度、点云密度或置信度标签，实际上并没有。第二阶段训练时，AQR 接收的是三分类传感器状态标签：

    yi={[0,1,0],LiDAR dropped,[1,0,0],Camera dropped,[0,0,1],Both modalities retained.\mathbf y_i= \begin{cases} [0,1,0], & \text{LiDAR dropped},\\ [1,0,0], & \text{Camera dropped},\\ [0,0,1], & \text{Both modalities retained}. \end{cases}yi​=⎩⎨⎧​[0,1,0],[1,0,0],[0,0,1],​LiDAR dropped,Camera dropped,Both modalities retained.​

    路由损失为：

    LAQR=∑i=1NCE⁡(yi,πi).\mathcal L_{\mathrm{AQR}} = \sum_{i=1}^{N} \operatorname{CE}(\mathbf y_i,\boldsymbol{\pi}_i).LAQR​=i=1∑N​CE(yi​,πi​).

    训练时同一帧的所有 queries 使用相同的样本级标签。例如整帧 LiDAR 被 drop 时，所有 queries 都被监督为选择 Camera Expert。AQR 因为只能查看每个 query 附近的局部特征，会逐渐把“局部 LiDAR 特征缺失”与 Camera 路径联系起来。

    但是，训练集并没有提供“第 17 个 query 的 LiDAR 局部损坏、第 18 个 query 的 LiDAR 正常”这种逐 Query 质量标签。因此，在 Limited FOV、Object Failure 等部分故障中进行不同的局部路由，是模型从完整模态 drop 训练中泛化出来的能力，而不是直接监督得到的严格最优选择。

    为什么必须限制为局部特征

    以 Limited FOV 为例，LiDAR 只在部分角度缺失。如果 AQR 对整张 LiDAR BEV 做全局注意力，大量正常区域会掩盖某个 query 所在区域的异常，使路由器仍可能判断“LiDAR 整体可用”，错误地把受影响 query 送入融合专家。Local Attention Mask 强制路由决策只依据目标候选附近的证据，从而让选择结果具有空间针对性。

    论文的消融结果支持这一点：

    配置Clean mAP/NDS鲁棒性比例 R mAP/NDS
    ME + AQR（全局注意力，无 LAM）71.0/73.674.1/83.2
    ME + AQR + LAM71.2/73.680.5/86.2

    加入 LAM 后，Clean 性能基本不变，而 RRR 的 mAP/NDS 分别提高 6.4/3.0 个百分点，说明提升主要来自故障场景下更合适的局部路由。

    补充材料进一步比较 AQR 内部的特征提取方法。在 Limited FOV 场景中：

    路由特征提取方式mAP/NDS
    全局 Cross-Attention25.7/48.0
    Deformable Attention32.1/50.1
    MLP44.2/54.4
    AQR + 显式 Local Attention Mask50.6/58.3

    这里比较的是 MoME 内部不同路由器设计，证明显式局部窗口有利于 MoME 的专家选择。对于普通检测特征提取，Deformable Attention 的自由采样很有价值；对于 AQR 这种故障路由任务，过度自由的采样可能绕开局部故障、稀释故障信号。显式 Local Attention Mask 通过固定局部支持、完整窗口覆盖和跨模态投影对应，使路由器真正看到 query 附近的模态状态，因此在 Limited FOV 等局部失效场景中性能差距会很大。

    理解 AQR 时容易混淆的边界

    1. AQR 不负责修复坏特征：它只决定绕过哪一种模态，真正的目标解码由被选专家完成。而局部窗口用于路由，不是局部特征融合结果：AQR 查看局部特征作出选择；被选专家仍读取其对应的完整特征 Memory。
    2. Query 级硬路由：每个 query 只经过一个专家，因此能避免坏模态进入该 query 的解码路径，但也可能丢掉另一模态仍然有用的互补信息。
    3. 三条专家路径不是三套完全独立参数：论文实现的 6 层 Transformer Expert Decoders 共享权重，主要解耦的是输入 Memory 与执行路径，而其部分故障能力来自泛化：训练只显式模拟整模态 drop；固定 5×55\times55×5、15×1515\times1515×15 窗口和样本级标签仍可能限制对未知局部故障的适应性。

    3.4 训练策略#

    训练时从三个互斥状态中均匀采样：drop camera、drop LiDAR、两者都保留，各占 1/3。虽只模拟完全失效，但因 AQR 路由使用局部特征，对部分失效也表现出一定泛化能力。

    两阶段训练：

    • 阶段 1：所有 query 并行过每个专家解码器，不用 sensor drop 增强。各专家用二分匹配 + GT 训练，损失 L1st=Ll+Lc+LlcL^{1st}=L_l+L_c+L_lcL1st=Ll​+Lc​+Ll​c（分类 focal loss + 回归 L1 loss）。
    • 阶段 2：冻结预训练的 backbone 和专家解码器，专训 AQR。此时模拟传感器失效（随机 drop）。生成监督标签：LiDAR dropped -> y=[0,1,0]（选 camera 专家）；camera dropped -> y=[1,0,0]（选 LiDAR 专家）；都不 drop -> y=[0,0,1]（选融合专家）。同一训练样本的全部 query 使用相同标签，用交叉熵损失 L2nd=ΣCE(yi,pi)L^{2nd}=Σ CE(y_i, p_i)L2nd=ΣCE(yi​,pi​)。
    • 训练时长：阶段 1 训练 backbone+专家 20 epoch，阶段 2 冻结上述网络后训练 AQR 2 epoch。

    注意：第二阶段以样本级标签显式监督 AQR 区分 LiDAR drop、camera drop 和双模态正常三种状态；对部分故障的局部路由能力来自泛化。

    4. 传感器失效场景与实验相关#

    4.1 传感器失效#

    nuScenes-R 5 种：

    • LiDAR Drop：所有点云移除
    • Limited FOV：扫描角限制到 [-60°, 60°]
    • Object Failure：每个 bbox 内 LiDAR 点以 50% 概率移除
    • Camera View Drop：所有多视角图像置零
    • Occlusion：预定义泥点 mask 贴到图像

    nuScenes-C：27 种腐蚀（天气/传感器/运动/物体/对齐），本文取极端天气（雾、雪、阳光眩光）。

    4.2 实验相关#

    实验设置

    • 数据集：nuScenes + nuScenes-R + nuScenes-C。
    • Backbone：VoVNet（图像）+ VoxelNet（LiDAR）。
    • 架构：专家解码器=6 层共享权重 Transformer decoder；AQR=单层 cross-attention；mask 尺寸 ll=5,lc=15l_l=5, l_c=15ll​=5,lc​=15。
    • 训练：两阶段—先训 backbone+专家 20 epoch，再冻结训 AQR 2 epoch；CBGS（仅阶段1）；数据增强=随机翻转/旋转/缩放/平移/GT 采样。
    • 对比方法：MetaBEV、CMT、UniTR、UniBEV、BEVFusion、TransFusion、DeepInteraction、SparseFusion 等。
    • 指标：mAP、NDS、相对性能比 R=mPR/PC。

    AQR 在不同场景下如何分配 query：

    • LiDAR 丢时 92% 转向 camera 专家（避开坏模态）。

    5. 局限性与启示#

    局限

    • 训练需要先训练 backbone/experts，再冻结它们训练 AQR，共两个阶段。
    • 只模拟完全失效训练，对罕见失效模式的鲁棒性仍有限（论文 future work 提到要开发更有效的失效模式模拟训练策略）。
    • 论文称该结构可集成到 Transformer-based 融合架构，但没有跨框架插件实验，因此其通用性仍需进一步验证。

    启示

    1. 模态执行路径解耦有助于鲁棒性：MoME 为不同 query 选择 camera/LiDAR/融合路径。
    2. 路由应利用局部特征：AQR 的 local attention mask 是关键—全局路由不够好，而使用显式监督路由器，用 [0,1,0] 等标签直接告诉 AQR 每种失效下该选谁，比让它自己学更稳。
    3. 分布式 query 处理省算力：每个 query 只过一个专家，复杂度接近单解码器（+4ms）。
    4. 训练时随机 drop 模态是 MetaBEV、CMT、MoME 等方法共同采用的重要范式。

    MoME 通过 三条共享 decoder 权重的模态专家执行路径（camera/LiDAR/融合） 与 Adaptive Query Router（基于局部注意力 mask 为每个 query 选择路径），配合含样本级显式路由标签的两阶段训练降低模态依赖，在 nuScenes-R 多数失效场景取得领先结果，且相对 CMT 延迟仅增加 4ms。它是 query-based 鲁棒融合的一种代表性路由方案。
