    模态任意、任务无关的鲁棒 BEV 感知框架（ICCV'23）

    本文提出 MetaBEV，以可学习的 meta-BEV queries 和模态特定的 deformable cross-attention，统一处理 camera、LiDAR 或两者任意组合；通过 Switched-Modality Training 应对传感器缺失，并用 M²oE 缓解 3D 检测与 BEV 地图分割的多任务冲突。在 nuScenes 上，完整模态检测 NDS 达 71.5、地图分割 mIoU 达 70.4；LiDAR 缺失时仍达到 42.6 NDS / 54.4 mIoU，显著优于 BEVFusion。

    MetaBEV：解决传感器故障的3D检测与地图分割 ICCV’23(CCF-A)

    项目页 https://chongjiange.github.io/metabev.html

    1. 研究背景与动机#

    (1) 要解决什么问题？ 真实世界里传感器损坏或缺失是不可避免的（镜头遮挡、LiDAR 部分损坏、beam 减少、甚至整个传感器失灵）。现有融合方法在这些场景下性能急剧下降甚至崩溃，直接威胁自动驾驶安全。

    (2) 指出现有融合方法的两大挑战

    挑战 1：Features Misalignment（特征不对齐） 现有方法（如 BEVFusion）用 CNN + 特征拼接融合，会强加像素级位置对应关系。引入几何相关噪声时，特征可能错位。根因：CNN 长距离感知弱、对输入自适应注意力有限。本文的六种 corruption 实验不包含标定扰动。

    挑战 2：Heavily Reliant on Complete Modalities（严重依赖完整模态）

    • Query-indexing 融合（论文列举 MVX-Net、PointPainting、PointAugmenting、EPNet）：通常依赖 LiDAR 与 2D Camera 特征的相互查询，一方缺失时性能显著下降。
    • Channel-wise 融合（如 BEVFusion）：靠 element-wise 操作（如逐元素相加）合并，缺一模态就输出错误。

    两者都强依赖完整模态，LiDAR/camera 缺失即崩溃。

    (3) MetaBEV 的核心思想 作者认为瓶颈在于”融合模块缺乏独立处理不同模态的设计”。于是提出 modality-arbitrary（模态任意）、task-agnostic（任务无关） 的学习范式：用一组可学习的 meta-BEV queries，通过跨模态注意力按需从 LiDAR 或 camera 或两者任意组合中聚合特征。

    2. 核心贡献#

    1. 提出 MetaBEV，一个能在任意传感器输入下保持鲁棒性的 BEV 感知框架，同时做 3D 检测 + 地图分割。
    2. 引入 M²oE（Multi-Task Mixture of Experts） 结构，缓解多任务联合学习的 task conflict（任务冲突）。
    3. 在论文发表时取得有竞争力的 nuScenes 结果，其中 BEV 地图分割达到当时 SOTA（70.4% mIoU）。

    3. 方法详解#

    3.1 整体架构#

    多模态输入 (Images + LiDAR Points)
        ↓
(a) Feature Encoder（模态特定编码器）
   - Camera: Swin-T -> 2D特征 -> LSS视角变换 -> Camera BEV 特征 Bc
   - LiDAR:  VoxelNet -> 体素化+稀疏3D卷积 -> LiDAR BEV 特征 Bl
        ↓
(b) BEV-Evolving Decoder（核心）
   - 外部初始化的 meta-BEV queries (Bm, 180×180)
   - N=4 层 Cross-Modal Attention（deformable，带模态特定MLP）
   - M=2 层 Self-Attention（建模 query 间关系）
   - 多任务设置下，以 M²oE-FFN 替换 BEV-Evolving block 中的普通 FFN
        ↓
   FPN 生成多尺度特征
        ↓
(c) Task-Specific Heads
   - Transformer head（TransFusion 风格）-> 3D 检测
   - CNN head（BEVFusion 风格）-> BEV 地图分割

    为什么用 BEV 空间？ BEV 提供统一域，把”几何不足的图像特征”和”缺语义的 LiDAR 特征”在统一域互补融合；且 BEV 规则网格便于接各种 task head。

    为什么不用 CNN 融合（如 BEVFusion）？ CNN 融合（concat+conv）在大规模 corruption 下表征能力有限，且因 weight-sharing 无法处理缺失模态。

    CNN 融合与 BEV-Evolving Decoder 对比的是“多模态 BEV 特征的融合方式”，两种融合流程如下：

    BEVFusion:

      Camera → Camera BEV ┐
                      ├→ 拼接 + CNN → 融合 BEV → 任务头
  LiDAR  → LiDAR BEV  ┘

    BEVFusion 一类方法通常采用：

    [BfusedCNN⁡(Concat⁡(Bc,Bl))] [ B_{\mathrm{fused}} \operatorname{CNN} \left( \operatorname{Concat}(B_c,B_l) \right) ][Bfused​CNN(Concat(Bc​,Bl​))]

    其中：

    • (BcB_cBc​)：相机分支生成的 BEV 特征；
    • (BlB_lBl​)：LiDAR 分支生成的 BEV 特征；
    • ConcatConcatConcat：沿特征通道拼接两种模态；
    • CNNCNNCNN：对拼接后的特征进行局部融合。

    这种方法的核心是：先将两种模态的 BEV 特征拼接，再通过 CNN 生成统一的融合特征。

    MetaBEV:

      Camera → Bc ┐
              ├→ meta-BEV queries + BEV-Evolving Decoder
  LiDAR  → Bl ┘                                       ↓
                                meta-BEV
                                   ↓
                                 任务头

    MetaBEV 不直接拼接 (BcB_cBc​) 和 (BlB_lBl​)，而是引入一组可学习的 meta-BEV queries。

    这些 queries 在 BEV-Evolving Decoder 中，通过模态专属的可变形交叉注意力，分别从相机和 LiDAR 的 BEV 特征中提取信息。经过多层解码器迭代后，queries 逐渐“演化”为融合后的 meta-BEV 表示，因此该模块被称为 BEV-Evolving Decoder。

    模块对应关系:

    可以将两者理解为：

    [BEVFusion 的 CNN Fusion⟷MetaBEV 的 BEV-Evolving Decoder] [ \boxed{ \text{BEVFusion 的 CNN Fusion} \quad\longleftrightarrow\quad \text{MetaBEV 的 BEV-Evolving Decoder} } ][BEVFusion 的 CNN Fusion⟷MetaBEV 的 BEV-Evolving Decoder​]

    也就是说，MetaBEV 使用 BEV-Evolving Decoder 代替了 BEVFusion 风格的 CNN 融合模块。

    结论：

    MetaBEV 的 BEV-Evolving Decoder 提供了一种更加动态、以 query 为中心的多模态融合机制，并且更容易适应相机或 LiDAR 模态缺失的情况。

    3.2 Camera / LiDAR 如何变成 BEV 特征#

    • Camera -> BEV：Swin-T 提取多视角 2D 特征 -> 遵循 LSS（Lift-Splat-Shoot）：预测深度 和几何投影，把特征 scatter 到 3D 体素 -> 压缩成 pillar 格式的 camera BEV 特征 BcB_cBc​。
    • LiDAR -> BEV：点云做 voxelization 和 稀疏 3D 卷积（VoxelNet）-> 得 LiDAR BEV 特征BlB_lBl​

    3.3 Meta-BEV Queries 是什么？怎么初始化？#

    • 定义：一组 稠密(dense) BEV queries，每个 query 代表 BEV 空间中某个网格的特征，记为 BmB_mBm​。
    • 初始化：作为外部初始化的可学习参数，分辨率 180×180（与 BEVFormer 对齐以便公平对比）。
    • 加 position embedding 后参与 cross-attention。
    • 作用：它是”模态无关的中间载体”，不绑定任何单一模态，作为 query 主动从 LiDAR/camera/both 的 BEV 特征中按需聚合信息 -> 实现 modality-arbitrary。

    类比理解：把 meta-BEV query 想成一张”空白俯视图”，它会主动去 LiDAR 和 camera 那里”问”自己每个格子该填什么。LiDAR 在就问 LiDAR，camera 在就问 camera，都在就都问。

    3.4 BEV-Evolving Decoder（核心创新）#

    有关 Deformable Attention ，可以单独阅读 Deformable DETR 原论文

    整体模块说明：

    (1) Cross-Modal Attention Layer#

    问题：原始 Deformable Attention 用一个统一 MLP 同时生成采样偏移 Δp 和注意力权重 A，无法灵活处理”任意模态输入”。

    改进：引入模态特定 MLP—C-MLP（专给 camera）和 L-MLP（专给 LiDAR），让不同模态各自生成采样偏移和权重。

    为什么原始统一 MLP 不够？

    在标准 Deformable Attention 中，通常由一套统一的线性层或 MLP 从 Query 预测 Offset 与 Attention Weight。

    论文直接给出的理由是：原始 DAttn 用一套统一 MLP 预测 Offset 和 Weight，不适合灵活处理任意可用输入。直观上，可以结合 Camera BEV 与 LiDAR BEV 的统计差异理解这一设计：

    • Camera BEV 来自深度估计与视角投影，可能存在较明显的几何投影误差；
    • LiDAR BEV 来自点云体素化，几何更直接，但点云稀疏；
    • 两种模态在发生故障或退化时，误差形态也不同。

    MetaBEV 为不同模态分别设置：

    • Camera 的 C-MLP；
    • LiDAR 的 L-MLP。

    它们都以当前 meta-BEV Query 为输入，但分别预测本模态的 Sampling Offsets 和 Attention Weights。

    计算流程（Figure 4 III）：

    1. 当前 value 集合可以是 {BcB_cBc​}、{BlB_lBl​} 或 {Bc,BlB_c, B_lBc​,Bl​}，query BmB_mBm​ 为各可用模态生成采样偏移 ΔpxΔp_xΔpx​ 和权重 AxA_xAx​；

    3. 用 AxA_xAx​ 对采样特征加权求和，更新 meta-BEV。

    为什么叫 Evolving

    设初始 meta-BEV 为 Bm(0)B_m^{(0)}Bm(0)​。每一层 Cross-Modal Attention 都会利用当前可用的传感器特征更新它：

    (2) Self-Attention Layer#

    Cross-Modal Deformable Attention 只建模 query 与 sensor 特征间的 inter-correlation，没显式建模 query 之间的 intra-correlation。

    Q=Bm,M∈{{c},{l},{c,l}},V={Br∣r∈M}.Q=B_m, \qquad \mathcal M\in \left\{ \left\{c\right\}, \left\{l\right\}, \left\{c,l\right\} \right\}, \qquad \mathcal V= \left\{ B_r\mid r\in\mathcal M \right\}.Q=Bm​,M∈{{c},{l},{c,l}},V={Br​∣r∈M}.

    这里 QQQ 是 Query 来源，BmB_mBm​ 是完整 meta-BEV Query Map；M\mathcal MM 决定当前有哪些传感器；V\mathcal VV 是由这些传感器对应的 BrB_rBr​ 组成的 Value 集合。它建模的是 meta-BEV Query 与传感器 BEV 特征之间的 Inter-Correlation。

    • 做法：把模态特定 MLP 降级为统一 MLP，输入 x 替换为 BmB_mBm​ 本身，即 DAttn(Bm,p,Bm)DAttn(B_m, p, B_m)DAttn(Bm​,p,Bm​)。
    • 数量：M=2 层。消融发现加 2 层 self-attention 提升 1.1 个 NDS 百分点。

    Deformable Self-Attention

    Cross-Attention 之后，不同 meta-BEV Query 之间还没有被显式充分建模。MetaBEV 将 Value 换为 BmB_mBm​，并把模态特定 MLP 改回统一 MLP。对第 qqq 个 Query 可记为：

    SelfDAttn⁡(bm,q,pq,Bm).\operatorname{SelfDAttn} \left( b_{m,q},p_q,B_m \right).SelfDAttn(bm,q​,pq​,Bm​).

    SelfDAttn 三个输入参数分别是：

    参数含义
    bm,qb_{m,q}bm,q​当前被更新的第 qqq 个 meta-BEV Query
    pqp_qpq​该 Query 在 BEV 网格中的参考坐标
    BmB_mBm​作为 Value 被采样的完整 meta-BEV Query Map
    SelfDAttn⁡\operatorname{SelfDAttn}SelfDAttn使用统一 Offset/Weight 预测 MLP 的可变形 Self-Attention

    论文正文使用的简写是 DAttn⁡(Bm,p,Bm)\operatorname{DAttn}(B_m,p,B_m)DAttn(Bm​,p,Bm​)。这里改名为 SelfDAttn⁡\operatorname{SelfDAttn}SelfDAttn，是为了与前面接收模态 Value 集合的 CrossDAttn⁡\operatorname{CrossDAttn}CrossDAttn 区分，并不表示增加了另一种采样算子。

    此时：

    Q=Bm,V=Bm.Q=B_m,\qquad V=B_m.Q=Bm​,V=Bm​.

    其中 QQQ 表示 Query 来源，VVV 表示 Value 来源。二者都等于 BmB_mBm​，因此它是 Self-Attention；与 Cross-Attention 的区别不在于是否使用 Offset，而在于 Query 和 Value 是否来自同一个表示。

    因此它属于 Self-Attention，并用于建模不同 BEV 网格 Query 之间的 Intra-Correlation。

    Self-Attention 中不再需要 C-MLP/L-MLP，而是退回统一的 Offset 和 Weight 预测 MLP，因为 Query 与 Value 已经都是融合后的 BmB_mBm​。

    (3) M²oE（Multi-Task Mixture of Experts）#

    多任务学习：3D 检测和地图分割如何联合？

    • 用同一套训练权重同时输出 3D 检测（Transformer head）和地图分割（CNN head）。
    • 痛点：多任务训练目标差异大 -> gradient conflict -> 各单任务性能下降。
    • 解决方案：引入 M²oE。

    M²oE是什么：受 NLP 大模型 MoE 启发，把 BEV-Evolving block 的 MLP/FFN 换成 MoE 形式，用于多任务学习。MetaBEV 是首个把 MoE 引入”3D 检测和 BEV 地图分割两种任务”的框架。

    两种变体（Figure 4 I/II）：

    (I) RM²oE（Routing M²oE，完整版带路由）： M2oE(x)=∑i=1tR(x)i Ei(x),t≪E\text{M}^2\text{oE}(x) = \sum_{i=1}^{t} \mathcal{R}(x)_i \, \mathcal{E}_i(x), \quad t \ll EM2oE(x)=∑i=1t​R(x)i​Ei​(x),t≪E

    • R 是路由函数（MLP），给每个 token 分配 expert；
    • EiE_iEi​ 是第 i 个 expert；用 sparse R 选 top-t（t≪E），其余 expert 不激活。

    (II) HM²oE（Hard MoE，简化退化版）：

    • E=任务数，去掉路由；token 直接过 task-specific FFN 再合并，省去 router 的额外计算。

    解决什么：训练时通过不同 expert 分离冲突梯度，缓解检测与分割的 task conflict。

    3.5 训练策略：Switched-Modality Training#

    • 训练时按预定概率随机接收不同模态输入，模拟传感器缺失。
    • 比例：camera / LiDAR / both 均匀 = 1/3 : 1/3 : 1/3。
    • 效果：只需一套预训练权重即可全场景部署。
    • 结果：该策略使完整模态检测 NDS 从 71.0 提升至 71.5（+0.5），但完整模态地图分割 mIoU 从 70.4 降至 68.5（-1.9）。

    (II) 实验设置#

    • 数据集：nuScenes（700/150/150 场景；数据集包含 6 cameras + 1 LiDAR + 5 radars，但 MetaBEV 实际只使用 camera 与 LiDAR）。
    • 网络：Camera=Swin-T，LiDAR=VoxelNet，decoder=4 cross + 2 self attention，meta-BEV 180×180。
    • 训练：AdamW + cyclical lr；完整模态检测训练 26 ep、分割训练 20 ep；CBGS；8×A100。SMT 从任务预训练权重继续训练，camera/LiDAR/both 比例为 1:1:1；主文分割 SMT 结果追加训练 8 ep。
    • 对比方法：BEVFusion、BEVFormer、M²BEV、TransFusion、CenterPoint 等。
    • 指标：检测 mAP/NDS；分割 mIoU（6 类：Drivable/Ped.Crosswalk/Walkway/StopLine/Carpark/Divider）。
    • 鲁棒性测试：zero-shot（直接测 corrupted）+ in-domain（corrupted 上训练再测）。

    6. 局限性与启示#

    局限

    • 相比 BEVFusion 系列轻量方案引入额外参数（约 54M vs 41M）。
    • 未来方向：轻量化（网络剪枝、token reduction）。
    • 只做到“采样分支部分解耦”，没有做到“融合表示和执行路径完全解耦”，因为虽然 Camera 和 LiDAR 使用不同的 C-MLP、L-MLP 来预测 Offset 和 Weight，但两部分最终仍然相加，而且MetaBEV 是逐层演化的，后续采样位置和权重也可能被间接影响。

    启示

    1. 模态解耦是鲁棒融合的关键：不把模态绑死在 element-wise 操作上，用 query 主动按需聚合，是应对缺失模态的思路。
    2. Switched-Modality Training 简单有效：随机切换模态可大幅改善缺失场景
    3. MoE 是多任务冲突的有效解法。

    MetaBEV 用”可学习 meta-BEV queries 与 模态特定 deformable cross-attention”，在switched-modality 训练策略 下训练，实现了模态任意、任务无关的鲁棒 BEV 感知，在传感器缺失/损坏场景下大幅超越 BEVFusion，并用 M²oE 缓解多任务冲突，在论文当时将 nuScenes BEV 地图分割提高到 70.4% mIoU。
