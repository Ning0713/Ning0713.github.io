    01 注意力机制#

    1. 最终value的意义#

    我在入门注意力机制，其中Q和K计算后是得到不同key的注意力分数，那使用注意力分数计算得到的最终的value，这个值是用来做什么的呢，能使用一段文本给我举例介绍吗

    最终计算得到的 Value，是当前词在融合了整个句子的上下文语境后，得到的一个“全新版”的特征表示。 它不再是一个孤立的词，而是一个“懂周围环境”的词。为了更直观地理解，我们用一段文本来举例。

    假设我们有两句话：

    1. “我 昨天 吃 了 一个 苹果”
    2. “我 昨天 买 了 一股 苹果”

    在这个例子中，我们把目光聚焦在 “苹果” 这个词上。刚读取到“苹果”时，它的初始状态（原始向量）只包含了字典里的基础含义——可能是水果，也可能是科技公司。

    现在，我们用注意力机制来更新“苹果”的特征： 第一步：计算注意力分数（Q 和 K 的作用）

    • 当模型处理第一句话时，“苹果”（Q）去环顾四周的词（K）。它发现自己和“吃”（K）的相关性极高，因此它们之间的注意力分数接近满分。
    • 在第二句话中，“苹果”（Q）环顾四周，发现和“吃”没关系了，但和“股”（K）以及“买”（K）的相关性极高，获得了很高的分数。

    第二步：提取并混合内容（V 的作用，也就是你的问题所在） 注意力分数计算出来后，我们要用它来对所有词的 内容/实质含义（Value） 进行加权求和。

    • 在第一句话里： “苹果”的新表示 = 90%“吃”的 V + 10% 其他词的 V + 自身基础的 V。最终得到的 Value： “苹果”这个词吸收了“吃”的属性，它的特征向量发生偏移，牢牢地指向了“一种汁水丰富的物理水果”。

    • 在第二句话里： “苹果”的新表示 = 90%“股”的 V + 10% 其他词的 V + 自身基础的 V。最终得到的 Value： “苹果”这个词吸收了“金融、股票”的属性，它的特征向量发生偏移，牢牢地指向了“一家市值庞大的科技巨头”。

    通过这套机制，大模型在阅读时就不会断章取义，而是拥有了真正的“全局视野”。

    2. 使用向量进行计算#

    在Happy-LLM中，对于符号命名并不严谨，并且会有之前是简单概念后面就是公式的割裂感，导致理解会出现偏差。

    深度学习引入了向量空间。这时候：在真实的注意力机制里，Query、Key 和 Value 全部都是高维向量（Vector），而不是单个的数字

    可以这样来理解这个从标量到向量的升级： 在游戏开发或者构建 3D 场景时，一个物体（比如苹果）不可能只用一个数字来表示。

    • Key 向量 (K)：相当于这个物体的“属性标签”。比如苹果的 KKK 可能是 [甜度: 0.8, 颜色: 红色(RGB), 是否可食用: 1.0]。
    • Query 向量 (Q)：相当于玩家发出的“搜索条件”。比如玩家肚子饿了，系统发出一个 QQQ：[甜度需求: 0.9, 颜色无所谓, 是否可食用: 1.0]。

    1. 点积算的是什么？ 我们将玩家的 QQQ 向量和苹果的 KKK 向量进行点积运算（Q⋅K）。点积计算的既包含了向量的模大小，也包含了它们在多维空间中的方向夹角（相似度）。点积结果越大，说明苹果的属性标签和玩家的需求越匹配（注意力分数高）。

    2. 最后的 Value 是什么？ 在算出了相似度（注意力分数）之后，我们要提取的最终 Value 也是一个高维向量 (V)，是单独给出的，与 KKK 向量的模值没有关系，可以把它想象成这个苹果在游戏里的完整数据。 所以，最终的计算过程是：

    最终结果=(注意力分数apple×Vapple)+(注意力分数banana×Vbanana)+…\text{最终结果} = (\text{注意力分数}_{\text{apple}} \times V_{\text{apple}}) + (\text{注意力分数}_{\text{banana}} \times V_{\text{banana}}) + \dots最终结果=(注意力分数apple​×Vapple​)+(注意力分数banana​×Vbanana​)+…

    如果 “fruit” 和 “apple” 的点积相似度是 0.9，和 “chair” 的相似度是 0.01。那么模型最终拿到手里的是 90%的苹果完整特征向量 和 1%的椅子特征向量 的混合体。

    4. 缩放点积注意力#

    这个公式被称为缩放点积注意力（Scaled Dot-Product Attention）。比基础公式，多了一个除以 dk\sqrt{d_k}dk​​ 的操作。

    1.高维度导致“方差爆炸”

    假设我们的 Query 和 Key 向量里的数字，都是从一个均值为 0、方差为 1 的标准正态分布中随机抽取的。

    点积的计算过程是按位相乘再相加：q⋅kT=∑i=1dkqikiq \cdot k^T = \sum_{i=1}^{d_k} q_i k_iq⋅kT=∑i=1dk​​qi​ki​

    • 如果维度 dk=2d_k = 2dk​=2，点积结果是由 2 个随机数相乘再相加，结果的波动范围（方差）大概是 2。
    • 如果维度 dk=512d_k = 512dk​=512，点积结果是由 512 个随机数累加而成。根据概率论，累加的项越多，结果的方差就越大。此时点积结果的方差会变成 512。

    直观理解： 维度越高，两个向量点积后产生的数值就越容易出现极端的“大数”或“极小数”。这就导致了不同词与词之间的初始注意力得分差距被拉得极其巨大。

    2.Softmax 的“赢家通吃”效应

    Softmax 的公式包含指数运算 exe^xex ，指数函数的特点是：对数值的差异极其敏感。 假设我们有三个词的初始得分：

    • 低维度 (dk=2d_k=2dk​=2) 时，得分差距较小，比如：[2, 0, -1] 经过 Softmax 后：[0.84, 0.11, 0.04] ←\leftarrow← 注意力分配健康
    • 高维度 (dk=512d_k=512dk​=512) 时，方差爆炸，得分差距被放大，比如：[50, 0, -20] e50e^{50}e50 是一个天文数字，而 e0=1e^0=1e0=1，e−20e^{-20}e−20 趋近于 0。 经过 Softmax 后：[0.999999..., 0.000000..., 0.000000...] ←\leftarrow← 赢家通吃。

    当维度很大时，Softmax 会把几乎 100% 的注意力全给了那个初始得分稍微高一点点的词，而其他词的注意力被压到了 0。

    3.梯度消失

    在反向传播更新神经网络时，我们需要计算 Softmax 的导数（梯度），Softmax 输出某个概率值 ppp 时，它的导数大致与 p(1−p)p(1 - p)p(1−p) 成正比。

    • 当 p=0.5p = 0.5p=0.5 时，导数最大，网络学得最快。
    • 当发生了“赢家通吃”，也就是 p≈1p \approx 1p≈1 或 p≈0p \approx 0p≈0 时： 导数 ≈1×(1−1)=0\approx 1 \times (1 - 1) = 0≈1×(1−1)=0 或者 导数≈0×(1−0)=0导数 \approx 0 \times (1 - 0) = 0导数≈0×(1−0)=0

    结论： 如果不加干预，在高维度下，Softmax 的输出会牢牢卡在 1 和 0 边缘。此时梯度等于 0，无论怎么训练，参数都不会再更新了。

    既然维度 dkd_kdk​ 让方差变成了 dkd_kdk​，那么在数学上，只要我们把点积的结果除以 dk\sqrt{d_k}dk​​，就能把方差重新拉回到 1。

    5. attention 代码理解#

    '''注意力计算函数'''
def attention(query, key, value, dropout=None):
    '''
    args:
    query: 查询值矩阵
    key: 键值矩阵
    value: 真值矩阵
    '''
    # 获取键向量的维度，键向量的维度和值向量的维度相同
    d_k = query.size(-1) 
    # 计算Q与K的内积并除以根号dk
    # transpose——相当于转置
    scores = torch.matmul(query, key.transpose(-2, -1)) / math.sqrt(d_k)
    # Softmax
    p_attn = scores.softmax(dim=-1)
    if dropout is not None:
        p_attn = dropout(p_attn)
        # 采样
     # 根据计算结果对value进行加权求和
    return torch.matmul(p_attn, value), p_attn

    理解张量（Tensor）的维度（Shape）变化。

    我们假设当前的输入张量形状为 (Batch, Seq_Len, Dim)，也就是 (批次大小, 句子长度, 词向量维度)。我来为你逐行拆解这段代码里的核心函数：

    1. 获取缩放因子：query.size(-1)
    d_k = query.size(-1)
    • 作用：获取张量的最后一个维度的大小。
    • 原理解析：在 PyTorch 中，-1 代表倒数第一个维度。由于 query 的形状是 (Batch, Seq_Len, Dim)，所以 query.size(-1) 提取出来的就是词向量的维度（比如 512）。这就是 dkd_kdk​。
    1. 矩阵转置：key.transpose(-2, -1)
    key.transpose(-2, -1)
    • 作用：将 key 张量的最后两个维度互换。
    • 原理解析：这是为了满足矩阵乘法的规则。
      • key 原本的形状是 (Batch, Seq_Len, Dim)。
      • 我们只想要交换句子长度和词向量维度，而不破坏前面的 Batch 结构。所以我们用 transpose(-2, -1)，把形状变成了 (Batch, Dim, Seq_Len)。这对应了数学公式里的 KTK^TKT。
    1. 批量矩阵乘法：torch.matmul(...)
    scores = torch.matmul(query, key.transpose(-2, -1)) / math.sqrt(d_k)
    • 作用：执行 Q×KTQ \times K^TQ×KT，计算每个词对其他词的原始注意力得分，并除以 dk\sqrt{d_k}dk​​ 完成缩放。
    • 原理解析：torch.matmul 函数，它支持批量矩阵乘法（BMM）。它会忽略前面的 Batch 维度，只对后两个维度执行标准的矩阵乘法：
      • (Batch, Seq_Len, Dim) ×\times× (Batch, Dim, Seq_Len) →\rightarrow→ 结果的形状变成了 (Batch, Seq_Len, Seq_Len)。
      • 这个 (Seq_Len, Seq_Len) 的方阵，就是注意力得分矩阵 比如句子有 10 个词，这就生成了一个 10×1010 \times 1010×10 的网格，记录了每个词和其他 9 个词的相关性。
    1. 归一化分配：scores.softmax(dim=-1)
    p_attn = scores.softmax(dim=-1)
    • 作用：在最后一个维度上执行 Softmax 操作，把原始得分变成概率权重。
    • 原理解析：scores 的形状是 (Batch, Seq_Len, Seq_Len)。dim=-1 意味着我们在每一行（也就是针对每一个具体的 Query 词）去横向比较它对所有 Key 词的得分，并把它们压缩成相加等于 1 的权重比例。
    1. 随机失活：dropout(p_attn)
    if dropout is not None:
    p_attn = dropout(p_attn)
    • 作用：防止模型过拟合。
    • 原理解析：它会随机把注意力矩阵里的一些权重强制变成 0。这就像在学习时故意遮住一部分信息，强迫模型去关注更多的上下文，而不是只死死盯着某一个词。

    02 自注意力机制#

    1. 理解自注意力#

    在真实的神经网络里，Q、K、V 到底是从哪里来的？

    我们暂时抛开干巴巴的符号，用一个 “机器翻译” 的真实场景来拆解这段话。 假设我们正在用 Transformer 模型把英文 "Apple is delicious" 翻译成中文 "苹果很好吃"。

    1.什么是“两段序列”？

    在翻译任务中，天然存在两段不同的文本序列：

    • 序列 A（历史信息/待生成信息）：我们目前已经翻译出来的中文，比如 ["苹果", "很"]。它在 Transformer 中被称为 Decoder（解码器） 的输入。

    • 序列 B（编码信息/源信息）：我们最初输入的英文原句，即 ["Apple", "is", "delicious"]。它在 Transformer 中被称为 Encoder（编码器） 的输出。

    2.Q、K、V 是如何在这两段序列中分配的？

    后半段话的核心：Q 来自于一个序列，K 与 V 来自于另一个序列。 当我们想预测 "很" 后面的下一个词时：

    • Query (Q) 来自序列 A（中文）：模型当前的状态是 "很"。它发出了一个查询请求（Q）：“我已经翻译了‘苹果很’，下一个词我该去英文原句里找哪个词来翻译？”
    • Key (K) 来自序列 B（英文）：英文句子里的每个词 ["Apple", "is", "delicious"] 都举起自己的标签（K）。delicious 的标签可能写着“形容词、味道好”。
    • Value (V) 也来自序列 B（英文）：英文句子里的每个词不仅有标签，还包含了它实际的语义内容（V）。

    此时，中文的 "很"（Q）和英文的 "delicious"（K）一拍即合，注意力分数极高。于是，模型顺理成章地提取了 "delicious" 的内容（V），从而成功预测出下一个中文字是 "好吃"。

    3.怎么理解“很少存在额外的真值 Value”？

    这句话是为了防止产生误解而加的补充说明，虽然表述得有些绕。 在数学公式 Attention(Q,K,V)Attention(Q, K, V)Attention(Q,K,V) 里，Q、K、V 是三个独立的变量。很多初学者会误以为，在实际应用中我们需要找三段不同的文本来分别充当这三个角色。

    作者是在强调：实际上我们只有两段物理文本（序列 A 和 序列 B）。

    • 序列 A 单独提供 Q。
    • 序列 B 同时包揽了 K 和 V 的角色。

    在底层代码中，序列 B 的同一个词向量（比如 "delicious"），分别乘以了两个不同的权重矩阵（WkW_kWk​ 和 WvW_vWv​），变身成了 K 向量和 V 向量。K 用来负责和 Q 算分数匹配，V 用来负责提供真实的特征内容。并没有凭空多出来一个“第三序列”去充当 Value。

    4.为什么要用自注意力

    为什么要在 Encoder（编码器）里不厌其烦地让句子里的每一个词都去和其他所有词算一遍相关性？

    简单用一句话概括：为了让每个原本孤立的词，进化成一个“完全懂这句话上下文”的词。

    自然语言最复杂的地方在于，词是没有绝对固定含义的，它的意思完全由周围的词决定。让每一个 token 互相计算相关性，主要是为了解决以下三个核心痛点：

    • 1.解决致命的“代词指代”问题（指代消解） 语言中充满了简写和代词。我们来看深度学习中极其著名的一个测试用例：
    • 句子 A： “这只动物没有穿过那条街道，因为它太累了。”
    • 句子 B： “这只动物没有穿过那条街道，因为它太宽了。”

    对于计算机来说，“它”只是一个毫无感情的代词 token。如果不看全局，模型根本不知道“它”是谁。

    有了自注意力机制：

    • 在句子 A 中，当“它”作为 QQQ 去寻觅全句的 KKK 时，由于句尾有“累了”这个语境，“它”会和“动物”产生极高的共鸣（注意力分数极高）。混合 VVV 之后，“它”的向量特征就变成了“疲惫的动物”。
    • 在句子 B 中，由于句尾有“宽了”，“它”的 QQQ 会和“街道”的 KKK 产生极高分数。混合后，“它”的向量特征就变成了“宽阔的街道”。

    通过让全句所有的词互相“握手”打分，模型完美破解了语言中的歧义。

    • 2.重塑多义词的灵魂（上下文融合）

    假设句子是：“我今天去苹果店买了一部手机，顺便吃了一个苹果。” 在输入给 Encoder 之前，这两个“苹果”在底层词典里的初始词向量是一模一样的。这显然不合理。 通过自注意力机制：

    • 第一个“苹果”会敏锐地和“店”、“买”、“手机”产生高昂的注意力分数，它最终输出的 VVV 会变成一个充满科技属性的实体向量。
    • 第二个“苹果”会和“吃”产生极高的关联，它的特征会偏移向水果属性。

    编码器的目的，就是要把原始文本“翻译”成机器能懂的高级特征矩阵。自注意力让输出的每一个向量都不再是死板的字典词，而是动态的、定制化的。

    • 3.全局视野 在 Transformer 诞生之前，大家用的都是 RNN（循环神经网络）或 LSTM。这类模型像人类读书一样，从左到右，一个词一个词地读。 这带来一个致命弱点：如果句子很长，当它读到第 100 个词时，早就把第 1 个词的细节忘光了（长距离依赖衰减）。

    在自注意力的矩阵运算中，不管词汇在句首还是句尾，它们之间的“物理距离”永远是 O(1)O(1)O(1)。第 1 个词和第 1000 个词可以直接进行点积 Q⋅KTQ \cdot K^TQ⋅KT 对话，没有任何信息损耗。这使得大语言模型拥有了极其恐怖的上下文统筹能力。

    最后一句话提到了“给 Q、K、V 的输入传入同一个参数”，这正是 Self-Attention 的精髓所在。 在之前讲的交叉注意力中，QQQ 来自中文句子，KKK 和 VVV 来自英文句子。

    但在编码器中，没有外人，只有当前这一句话。 假设输入文本经过最初步的转化后，变成了一个张量矩阵 XXX。模型会使用这同一个张量 XXX，去分别乘以三个不同的线性权重矩阵（WQ,WK,WVW^Q, W^K, W^VWQ,WK,WV），从而自己分裂出自己的 Q、K、V： Q=X⋅WQQ = X \cdot W^QQ=X⋅WQ K=X⋅WKK = X \cdot W^KK=X⋅WK V=X⋅WVV = X \cdot W^VV=X⋅WV

    这就像是一个人（输入序列 XXX）站在三面不同角度的镜子前，照出了自己的三个分身。然后这三个分身互相打分、互相融合，最终完成了一次对自我的深度审视和升华。

    2. 掩码自注意力#

    第一，掩码注意力（Masked Attention）是用在解码器里面吗？ 是的。截图里提到的这种“上三角掩码（Causal Mask）”是解码器的标志性特征。

    第二，它是用于计算编码器送来的 K、V 与解码器自身的 Q 吗？

    掩码代码，是用在解码器的掩码自注意力层（Masked Self-Attention），此时的 Q、K、V 全部来自解码器自身。

    而“Q来自解码器，K、V来自编码器”的层叫做交叉注意力层（Cross-Attention），在这个层里，解码器是可以纵览编码器所有内容的，通常不需要加这种遮蔽未来的上三角掩码。

    假设我们在做机器翻译，要把 “I love you” 翻译成 “我 爱 你”。 在训练阶段，我们其实是把整句正确答案 ["我", "爱", "你"] 一次性喂给解码器的。

    当我们训练模型预测 “我” 的下一个词是 “爱” 时，模型面前其实已经摆着完整的 ["我", "爱", "你"] 序列了。如果不加限制，第 1 个词 “我” 的 QQQ 去和全句的 KKK 算相似度时，它会偷偷“偷看”到后面的答案，这就变成了作弊。

    为了防止作弊，我们人为引入了一个掩码矩阵（Mask）。规则很简单：每个词只能看到它自己和它之前的词，绝对不能看到它后面的词。

    Mask 矩阵维度一般为 (1, seq_len, seq_len)

    scores = scores + mask[:, :seqlen, :seqlen]
    • scores：这是原始的注意力打分矩阵（形状是 seqlen x seqlen），也就是 Q⋅KTQ \cdot K^TQ⋅KT 的结果。
    • mask[:, :seqlen, :seqlen]：这是一个预先生成好的矩阵。在这个矩阵中，下三角区域（包括对角线）全为 0，而上三角区域全是负无穷（-inf，在代码里通常用一个极小的负数比如 -1e9 表示）。
    • 核心逻辑：当 scores 和 mask 相加时：
      • 对于过去和现在的词（下三角）：原始分数 +0=+ 0 =+0= 分数不变。
      • 对于未来的词（上三角）：原始分数 +(−∞)=+ (-\infty) =+(−∞)= −∞-\infty−∞。
    scores = F.softmax(scores.float(), dim=-1).type_as(xq)

    这短短一行包含了三个非常专业的工程操作：

    1. scores.float() (精度提升)：在训练大模型时，为了省显存，输入 xq 通常是半精度浮点数（FP16 或 BF16）。但在做 Softmax 这种包含指数运算的操作时，半精度极其容易溢出（变成 NaN）。所以这里先强制把数据转成单精度（FP32）以保证计算的绝对稳定。
    2. F.softmax(..., dim=-1) (核心魔法)： 由于我们在上一步把“未来词”的分数都变成了 −∞-\infty−∞。根据 Softmax 的公式包含 exe^xex： e−∞=0e^{-\infty} = 0e−∞=0 这就是掩码最精妙的地方！经过 Softmax 后，所有本来试图偷看“未来词”的注意力权重，被物理意义上硬生生地变成了 0。 模型把 100% 的注意力被迫全部分配给了当前词和过去的词。
    3. .type_as(xq) (精度还原)：Softmax 算完（且安全了）之后，把 FP32 的数据重新降级回半精度（比如 FP16），和最原始的输入 xq 保持一致，继续往下传给后续的神经网络，深藏功与名。

    在 Decoder（解码器）中，数据的真实流动是这样的两段式

    1. 第一关：掩码自注意力（Masked Self-Attention）
      • Q、K、V 全是解码器目前生成的中文序列。
      • 必须使用 -inf 掩码代码，严格防止偷看后面的中文。
    2. 第二关：交叉注意力（Cross-Attention）
      • Q 是刚才第一关输出的中文特征，K 和 V 是编码器送来的英文全句特征。
      • 不用上三角掩码。因为英文原句早就写死了，不管当前翻译到哪个中文字，它都有权力去看整句英文上下文。

    掩码自注意力的K,V算出来是做什么的

    在掩码自注意力中，KKK 和 VVV 被计算出来，并且当场就被“消耗”掉了

    在真实的解码器块（Decoder Block）里，数据是像接力赛一样流转的。我们把解码器里的这两个注意力层，比作两次会议：

    掩码自注意力

    • 参与者： 只有解码器自己生成的中文词（比如 ["<BOS>", "我", "爱"]）。
    • 生成 Q、K、V： 这里的中文词向量 XXX，克隆出 QselfQ_{self}Qself​、KselfK_{self}Kself​、VselfV_{self}Vself​。

    在这个层里，它们当场就进行了完整的注意力计算

    “爱” 的 QselfQ_{self}Qself​，去和过去词的 KselfK_{self}Kself​（“<BOS>”, “我”, “爱”）算分数，然后混合它们对应的 VselfV_{self}Vself​。

    • 第一场会议的输出： 得到一个全新升级的 X′X'X′。这个 X′X'X′ 里的“爱”，已经完美融合了“我”的语境。

    • K 和 V 的结局： 第一场会议结束，这些 KselfK_{self}Kself​ 和 VselfV_{self}Vself​ 已经完成了它们的使命（被合成了 X′X'X′）

    交叉注意力

    现在，带着升级版的 X′X'X′，解码器来到了第二关，要去看编码器翻译的英文原句了。

    • Q 的来源： 刚才第一场会议输出的升级版中文特征 X′X'X′，化身成了这里的 QcrossQ_{cross}Qcross​。（代表：我现在的中文语境是这样的，我该找哪个英文词？）
    • K、V 的来源： 编码器送来的英文原句（比如 ["I", "love"]），分裂成了这里的 KcrossK_{cross}Kcross​ 和 VcrossV_{cross}Vcross​。
    • 计算： 中文的 QcrossQ_{cross}Qcross​ 和英文的 KcrossK_{cross}Kcross​ 算分数，提取英文的 VcrossV_{cross}Vcross​。

    工程现实中的 KV Cache

    虽然在数学推导上，第一场会议的 KselfK_{self}Kself​ 和 VselfV_{self}Vself​ 算完就被丢弃了，但在真实的代码推理（Inference）阶段，系统会把它们悄悄存进显存里（这就是大名鼎鼎的 KV Cache）。

    为什么？

    因为当模型下一轮要预测“你”这个词时，前置序列变成了 ["<BOS>", "我", "爱", "你"]。

    如果没有 Cache，模型为了计算“你”的分数，又要让“我”和“爱”重新生成一遍它们的 KselfK_{self}Kself​ 和 VselfV_{self}Vself​。这太浪费算力了！

    有了 KV Cache，模型只需要计算最新词“你”的 QselfQ_{self}Qself​，然后直接去显存里把之前算好存起来的 KselfK_{self}Kself​ 和 VselfV_{self}Vself​ 调出来，拼在一起算点积就可以了。

    3. 解码器结构#

    整个解码器（Decoder）数据流的物理起点是哪里？

    在数据进入那套复杂的 Q、K、V 矩阵乘法之前，必须有一个最原始的输入张量 XXX。这个 XXX 并不是凭空产生的，它是从我们人类的文本经过一系列物理转换后得到的。

    依然用把 “I love you” 翻译成 “我 爱 你” 为例。

    这个原始的 XXX 的诞生，主要经历了三个极其关键的预处理步骤：

    第一步：获取当前的文本序列

    解码器的输入 XXX，本质上就是“目前已经翻译出来的结果”。 但是这里有一个问题：当模型刚开始翻译，连第一个字都还没吐出来的时候，输入是什么？

    为了启动这个过程，深度学习里引入了一个特殊的占位符，通常叫 <BOS> (Begin Of Sentence，句子开头) 或者 [START]。

    • 第一轮生成： 此时解码器手里只有 ["<BOS>"]。
    • 第二轮生成： 假设上一轮模型成功预测了“我”，此时解码器手里的序列变成了 ["<BOS>", "我"]。
    • 第三轮生成： 变成了 ["<BOS>", "我", "爱"]。 （每一轮都通过掩码自注意力＋交叉注意力） 这个不断变长的中文序列，就是 XXX 的数据源头。

    第二步：查字典（Token Embedding 词向量嵌入）

    计算机不认识 <BOS> 也不认识“我”，它只认识数字。所以，我们要把文本序列变成向量。

    模型内部自带一本极其庞大的“字典”（Embedding Table）。字典里有几万个词，每个词都对应着一个长度为 Dim（比如 512 维）的浮点数向量。

    • 序列 ["<BOS>", "我", "爱"] 被送进字典。
    • 查表后，它变成了一个形状为 (3, 512) 的矩阵。
      • 第 1 行是 <BOS> 的专属 512 维向量。
      • 第 2 行是“我”的专属 512 维向量。
      • 第 3 行是“爱”的专属 512 维向量。

    这就是 词嵌入（Word Embedding）。

    第三步：贴上时间戳（Positional Encoding 位置编码）

    如果只做第二步，会有个致命缺陷：自注意力机制是同时处理所有词的，它根本没有“先后顺序”的概念。在它眼里，“我爱你”和“你爱我”计算出来的结果是一模一样的。

    为了让模型知道词的先后顺序，研究人员发明了位置编码（Positional Encoding）。

    这也是一个形状为 (3, 512) 的矩阵，但它里面的数字和词意无关，纯粹是代表物理位置的数学公式（通常是正弦和余弦函数）。

    • 第 1 行代表“绝对位置 1”的信号。
    • 第 2 行代表“绝对位置 2”的信号。
    • 第 3 行代表“绝对位置 3”的信号。

    第四步：张量 XXX 诞生

    最后一步：把词嵌入矩阵和位置编码矩阵，直接加起来 X=Word Embedding+Positional EncodingX = \text{Word Embedding} + \text{Positional Encoding}X=Word Embedding+Positional Encoding 现在，我们得到了一个形状依然是 (3, 512) 的矩阵 XXX。 这个 XXX 里的每一行（每一个词向量），既包含了词汇本身的含义（我是谁），又包含了它在句子里的顺序（我在哪）。

    它会被再次正式送入解码器的第一层（掩码自注意力层）。然后，这个新的 XXX 会克隆出三份，分别去乘以 WQW^QWQ、WKW^KWK、WVW^VWV 矩阵，裂变成属于它自己的 Q、K、V，开始执行我们之前自注意力打分机制(后面可能生成终结符 <EOS>)

    4. 多头注意力机制#

    1). 为什么使用多头注意力#

    你的前提完全正确：单次自注意力机制，确实已经让一个词和全句所有的词都进行了计算。 既然每个词都看遍了全句，为什么还要搞个“多头（Multi-Head）”呢？

    这里的核心盲区在于：“看遍了所有词” 不等于 “看懂了所有维度的关系”。

    用一个“专家会诊”的比喻，来彻底拆解它。

    1 直观比喻：为什么一个“头”不够用？

    假设我们有一句话：“小明 笑着 咬了 一口 甜甜的 苹果”。

    在单头注意力（Single-Head Attention 中，就只有一个专家在审视这句话。这个专家虽然看遍了全句所有的词，但他可能是一个 “语法专家”。

    • 他的眼中只有主谓宾关系。当他看到“咬了”（Query）时，他的注意力绝大部分都分配给了“小明”（主语）和“苹果”（宾语）。
    • 他完美拟合了动作关系，但他完全忽略了情感和状态。

    而在多头注意力（Multi-Head Attention） 中，Transformer 雇佣了 8 个甚至 96 个不同领域的专家（Head）同时来看这句话：

    • 头 1（语法专家）： 依然把“咬了”的注意力分配给“小明”和“苹果”。
    • 头 2（情感专家）： 当看到“小明”时，把极高的注意力分配给了“笑着”。
    • 头 3（属性专家）： 当看到“苹果”时，死死地盯住了“甜甜的”。
    • 头 4（指代专家）： 专门寻找代词和实体的联系（虽然这句没有代词）。

    结论： 每一个“头”确实都在做全局扫描（和所有词算分数），但因为它们各自掌管的参数权重矩阵（WQ,WK,WVW^Q, W^K, W^VWQ,WK,WV）不同，它们**“眼中在乎的东西”完全不一样**。最后把这 8 个专家的意见拼在一起，大模型才能全方位无死角地理解这句话。

    2). 如何实现多头注意力#

    在代码和张量（Tensor）层面，多头到底是怎么实现的？

    假设我们的 hidden_size = 512，并且我们设置了 num_heads = 8（8 个头）。

    如果不使用多头： 模型用完整的 512 维特征去算一次庞大的点积，得出一张 (seq_len, seq_len) 的注意力分数网格。由于 512 维揉在一起算总分，很多微妙的、局部的特征关系（比如“甜甜的”）很容易被占主导地位的宏观特征（比如主谓宾）给平均掉、掩盖掉。

    使用多头的精妙物理操作： Transformer 在拿到 512 维的 Q,K,VQ, K, VQ,K,V 张量后，做了一个极其聪明的动作——切片（Split） 它在 hidden_size 这个维度上，把 512 平均切成了 8 份！

    • 512÷8=64512 \div 8 = 64512÷8=64。
    • 现在，每一个头（Head）只分到了 64 维的特征。

    张量的维度在这个瞬间发生了华丽的变形： 原本的 (batch_size, seq_len, 512) 被 reshape 成了 →\rightarrow→ (batch_size, 8个头, seq_len, 64) 接下来，这 8 个头拿着自己专属的 64 维特征，互不干扰地、并行地去算自己的注意力分数。

    • 头 1 用 0~63 维算出一张 (seq_len, seq_len) 的关系网。
    • 头 2 用 64~127 维算出另一张完全不同的 (seq_len, seq_len) 关系网。 …
    • 一共算出了 8 张不同的关系网格！

    最后一步：拼接（Concatenate） 等这 8 个头各自算完自己那 64 维特征融合后的全新 VVV 后，Transformer 再把这 8 个 64 维的输出原封不动地拼接（Concat）回去。 64×8=51264 \times 8 = 51264×8=512

    当年提出 Transformer 的论文《Attention Is All You Need》中，关于多头注意力的原理解释是这样的：

    为了让 8 个头关注不同的东西，我们为这 8 个头各自准备了独立且不同的小型权重矩阵（W1Q,W2Q…W8QW_1^Q, W_2^Q \dots W_8^QW1Q​,W2Q​…W8Q​），每个小矩阵的形状是 (512, 64)。初始词向量 XXX 分别去乘这 8 个小矩阵，得到 8 个不同的、64 维的小 QQQ。

    但这样写因为这就意味着你要写一个 for 循环，让 GPU 算 8 次小矩阵乘法。GPU 最讨厌零碎的小计算，它最擅长的是一次性算一个无比巨大的矩阵。

    所以要使用了一个极其优雅的数学等价替换：

    1. 拼装大矩阵： 把那 8 个 (512, 64) 的小权重矩阵，在内存里横向拼成一个巨大无比的权重矩阵 WQW^QWQ，它的形状变成了 (512, 512)。
    2. 让初始词向量 XXX 直接和这个巨大的 WQW^QWQ 做一次矩阵乘法。 Qbig=X⋅WQQ_{\text{big}} = X \cdot W^QQbig​=X⋅WQ 此时，我们得到了一整个 512 维的 QQQ。
    3. 切片分配（Split/Reshape）： 然后，我们在得到这 512 维的 QQQ 之后，拿刀把它均分成 8 份，每份 64 维。

    在真正的代码里，这个“切片”操作只需要改变张量的“看法（View）”和“维度转置（Transpose）”。

    数据流是这样的：

    1. 生成大 Q： 形状为 (batch_size, seq_len, 512)。
    2. View变形（切片）： 告诉系统，不要把它当成 512 维，把它当成 8 个 64 维。 形状变成了 (batch_size, seq_len, 8, 64)。
    3. Transpose转置（为多头并行做准备）： 把“头”的维度换到前面去。 形状最终变成 (batch_size, 8, seq_len, 64)！

    现在，GPU 会把这个张量看作是 8 个互不干扰的独立宇宙。在接下来的注意力分数计算 Q⋅KTQ \cdot K^TQ⋅KT 中，这 8 个头会在底层的 CUDA 核心里同时进行点积计算。

    在标准的 Transformer 架构（包括现在的 GPT、Gemini 等所有大语言模型）中，只要提到注意力机制，默认全部都是多头（Multi-Head）的。

    解码器（Decoder）里面其实包含了两种注意力层，它们全都是多头体制：

    1. 多头掩码自注意力（Masked Multi-Head Self-Attention）： 也就是你问的这个。用于审视已经生成的文本，严格防止偷看未来。
    2. 多头交叉注意力（Multi-Head Cross-Attention）： 用于在生成当前词时，去原文本（编码器输出）里寻找线索。

    为什么掩码自注意力也必须是多头？ 因为解码器在预测下一个词时，同样面临极其复杂的语言环境。

    假设已经生成的中文是：“我 笑着 咬了 一口 甜甜的”，现在要预测下一个词（苹果）。 解码器同样需要请出所有的“专家（Heads）”来审视这句半成品：

    • 头 1（动作专家）： 盯住“咬了”，说明下一个词大概率是食物。
    • 头 2（属性专家）： 盯住“甜甜的”，进一步缩小范围。
    • 头 3（情感专家）： 盯住“笑着”，奠定正向的情感基调。

    所以，多头机制对于解码器来说同样是不可或缺的灵魂。

    跑一遍这段底层代码的维度变化。这会彻底打通这两者的关系 假设 batch_size = 32，seq_len = 5，num_heads = 8，总维度 hidden_size = 512（切分后每个头 64 维）。

    第一步：计算多头分数（Scores） 经过我们上一轮聊过的切片和转置后，QQQ 和 KKK 的维度变成了 (32, 8, 5, 64)。 它们做点积 Q⋅KTQ \cdot K^TQ⋅KT（在最后两个维度上运算）后，64 维被消耗掉了，分数矩阵的维度变成了 Scores→(32,8,5,5)Scores \rightarrow (32, 8, 5, 5)Scores→(32,8,5,5)

    (翻译：32 句话，8 个独立的专家头，每个头都算出了一张 5x5 的关系网格)

    第二步：掩码（Mask）

    现在高潮来了，我们的 Mask 矩阵应该是什么维度？需要给 8 个头分别准备不同的 Mask 吗？

    不需要。

    无论你是“语法专家”还是“情感专家”，都绝对不能偷看未来的词。防作弊规则对所有的头一视同仁。

    所以，我们依然只生成那个最基础的、上三角全是 -inf 的 5×55 \times 55×5 网格。为了利用 PyTorch 的广播（Broadcasting）机制，我们会把它的维度定义为： Mask→(1,1,5,5)Mask \rightarrow (1, 1, 5, 5)Mask→(1,1,5,5) 第三步：完美叠加（相加）

    scores = scores + mask

    在执行这行代码的瞬间，PyTorch 极其聪明地把这个 (1, 1, 5, 5) 的 Mask：

    1. 在 batch 维度上复制了 32 份。
    2. 在 head 维度上复制了 8 份。 瞬间覆盖到了所有批次、所有专家的每一张关系网格上！随后大家一起平平安安地去做 Softmax。

    3). 理解公式#

    MultiHead(Q,K,V)=Concat(head1,...,headh)WO\text{MultiHead}(Q, K, V) = \text{Concat}(\text{head}_1, ..., \text{head}_h)W^OMultiHead(Q,K,V)=Concat(head1​,...,headh​)WO headi=Attention(QWiQ,KWiK,VWiV)\text{head}_i = \text{Attention}(QW_i^Q, KW_i^K, VW_i^V)headi​=Attention(QWiQ​,KWiK​,VWiV​)

    这个公式用极其精炼的数学语言，把整个多头注意力的流水线严丝合缝地描述了出来。

    为了彻底吃透它，我们应该从下往上看，也就是先看下面那行局部的 head 是怎么算的，再看上面那行整体是怎么拼接的。

    第一步：局部计算 headi=Attention(QWiQ,KWiK,VWiV)\text{head}_i = \text{Attention}(QW_i^Q, KW_i^K, VW_i^V)headi​=Attention(QWiQ​,KWiK​,VWiV​) 这行公式解释了第 iii 个“专家头”是如何独立工作的。

    这里的 Q,K,VQ, K, VQ,K,V 其实指的是初始的输入张量（比如编码器输出的 512 维特征序列）。

    • WiQ,WiK,WiVW_i^Q, W_i^K, W_i^VWiQ​,WiK​,WiV​ 是什么？ 它们就是我们上文提到的，属于第 iii 个专家的专属小型投影矩阵（在理论层面，它们的形状是 512 x 64）。
    • QWiQQW_i^QQWiQ​ 在干什么？ 这是让初始的 512 维输入，去乘以这个专家的专属矩阵。这就好比让输入数据戴上了这位专家特制的“有色眼镜”。经过乘法后，原本 512 维的庞杂特征，被提炼、压缩成了 64 维的专属特征。
    • Attention(...)\text{Attention}(...)Attention(...) 在干什么？ 当这三个 64 维的专属小 Q、小 K、小 V 准备好之后，它们就去执行我们最熟悉的那套“点积 →\rightarrow→ 缩放 →\rightarrow→ Softmax →\rightarrow→ 乘以 V”的标准单头注意力流程。

    结论： 经过这一行公式，第 iii 个头算出了一个融合了上下文的 64 维输出特征。如果有 8 个头，我们就得到了 8 份不同的 64 维特征。

    第二步：全局组装

    MultiHead(Q,K,V)=Concat(head1,...,headh)WO\text{MultiHead}(Q, K, V) = \text{Concat}(\text{head}_1, ..., \text{head}_h)W^OMultiHead(Q,K,V)=Concat(head1​,...,headh​)WO

    这行公式是整个多头机制的“收尾点睛之笔”，它分为两个至关重要的动作：

    动作一：Concat\text{Concat}Concat（无缝拼接）

    把刚才那 8 个独立算出来的 64 维特征，像拼积木一样横向拼接起来。

    64+64+64+…（拼8次）=51264 + 64 + 64 + \dots \text{（拼8次）} = 51264+64+64+…（拼8次）=512

    此时，张量的维度重新胖回了原来的 512 维。但注意，这时的 512 维其实是 8 个互不相干的“知识区块”硬凑在一起的。

    动作二：WOW^OWO（终极融合矩阵）

    这是很多初学者最容易忽略，但工程上绝对不可缺少的一个矩阵！

    WOW^OWO （Output Weight Matrix）是一个巨大的、形状为 512 x 512 的权重矩阵。

    为什么必须要有 WOW^OWO？

    如果不乘 WOW^OWO，那拼接出来的 512 维特征就只是一个“大杂烩”。头 1（语法专家）和头 2（情感专家）的特征虽然靠在了一起，但它们彼此之间并没有交流。

    将拼接后的特征再乘以 WOW^OWO，就相当于召开了一次总结大会。WOW^OWO 这个“大老板”会将这 8 个专家的意见进行跨维度的加权混合、重新洗牌。经过这次终极运算后，输出的 512 维张量才是一个真正融会贯通、浑然一体的全新特征表示。

    那K,V需要分成八个吗?

    “既然我已经派出了 8 个不同的专家（8 个 QQQ）去提问了，那让他们去查阅同一个公共的资料库（1 个 KKK 和 1 个 VVV）不就行了吗？为什么连资料库也要切成 8 份？”

    直接回答你的结论：不行。KKK 和 VVV 必须、且绝对要跟着分成 8 份（或者说通过 8 组不同的权重矩阵计算出来）。

    如果不把 KKK 和 VVV 分开，多头注意力机制就会彻底失效。我们可以从“业务逻辑”和“数学规则”两个极其硬核的维度来彻底解开这个谜团。

    业务逻辑层：不同的专家，需要不同的“索引”和“内容”

    还记得我们说的“专家会诊”比喻吗？多头注意力的核心，是让不同的头在不同的特征子空间（Sub-spaces） 工作。

    假设输入词是“苹果”。

    • QQQ (提问)：专家在找什么。
    • KKK (键/标签)：词汇挂在身上的特征标签（用来和 Q 匹配）。
    • VVV (值/实质内容)：词汇实际包含的语义信息。

    如果只分 8 个 QQQ，但不分 KKK 和 VVV（让大家共享 512 维的 KKK 和 VVV）：

    • 语法专家（头1的 QQQ） 来找主语。他看着那个庞杂的 512 维公共 KKK（里面既有语法信息，又有颜色、味道、金融信息），他会被干扰，很难精准匹配。
    • 当他好不容易匹配上了，他提取出的公共 VVV 是一个大杂烩。他明明只想提取“名词属性”，却被迫把“红彤彤、甜甜的、乔布斯”这些多余的信息全带走了。

    这就是为什么要切分出 8 个 KKK 和 8 个 VVV：

    • 输入 XXX 乘以 W1KW_1^KW1K​，生成了头 1 专属的 K1K_1K1​。这相当于给“苹果”贴上了纯粹的**“语法标签”**。
    • 输入 XXX 乘以 W1VW_1^VW1V​，生成了头 1 专属的 V1V_1V1​。这相当于把“苹果”的内容提纯成了纯粹的**“名词实体信息”**。
    • 现在，语法专家的 Q1Q_1Q1​ 只和语法标签 K1K_1K1​ 匹配，提取纯粹的语法内容 V1V_1V1​。整个链路干净、纯粹、互不干扰！

    同理，**情感专家（头2）**拥有自己专属的 K2K_2K2​（情感标签）和 V2V_2V2​（情感内容）。这样，同一个词“苹果”，在 8 个头眼里，展现出了 8 种完全不同的侧面。这才是“全面深入拟合语言信息”的真谛。

    如果你尝试在代码里写出“8 个 QQQ，共享 1 个 KKK”的代码，PyTorch 会在运行的第一秒就给你报红报错。

    为什么？因为注意力机制的核心运算是点积（Dot Product）：

    Scores=Q⋅KT\text{Scores} = Q \cdot K^TScores=Q⋅KT

    • 如果你把 QQQ 分成了 8 份，那么每一个小 QiQ_iQi​ 的维度就变成了 64 维。

    • 如果你不分 KKK，保留公共的 KKK，那它的维度依然是 512 维。

    • **数学法则规定：一个 64 维的向量，是无法和一个 512 维的向量做点积的

    为了能和 64 维的 QiQ_iQi​ 算分数，KKK 必须也被降维（切分）到 64 维，变成 KiK_iKi​。 算完分数后，这个分数要乘以 VVV 来混合特征。为了保证最后 8 个头拼接起来（64×864 \times 864×8）能刚好还原成 512 维，每一个小 ViV_iVi​ 也必须是 64 维。

    工程代码是怎么写的？

    在真实的 Transformer 代码底层，Q,K,VQ, K, VQ,K,V 的生成待遇是完全平等、完全一致的。

    1. 代码会同时初始化三个巨大的权重矩阵：WbigQ,WbigK,WbigVW_{big}^Q, W_{big}^K, W_{big}^VWbigQ​,WbigK​,WbigV​（形状都是 512 x 512）。
    2. 输入 XXX 分别和这三个大矩阵相乘：
      • Qbig=X⋅WbigQQ_{big} = X \cdot W_{big}^QQbig​=X⋅WbigQ​
      • Kbig=X⋅WbigKK_{big} = X \cdot W_{big}^KKbig​=X⋅WbigK​
      • Vbig=X⋅WbigVV_{big} = X \cdot W_{big}^VVbig​=X⋅WbigV​
    3. 然后，代码会极其公平地，把 Qbig,Kbig,VbigQ_{big}, K_{big}, V_{big}Qbig​,Kbig​,Vbig​ 同时切成 8 份。
      • 第 1 份的 Q1,K1,V1Q_1, K_1, V_1Q1​,K1​,V1​ 组成第一套头 1。
      • 第 2 份的 Q2,K2,V2Q_2, K_2, V_2Q2​,K2​,V2​ 组成第二套头 2。
      • 以此类推……

    总结一下疑惑： 不能只让“提问者（Q）”分身，必须让“资料的索引（K）”和“资料的内容（V）”也跟着分身。只有这样，模型才能在不同的特征子空间里，进行互不干扰、极其纯粹的专业计算。

    4). 代码理解#

    import torch.nn as nn
import torch

'''多头自注意力计算模块'''
class MultiHeadAttention(nn.Module):

    def __init__(self, args: ModelArgs, is_causal=False):
        # 构造函数
        # args: 配置对象
        super().__init__()
        # 隐藏层维度必须是头数的整数倍，因为后面我们会将输入拆成头数个矩阵
        assert args.dim % args.n_heads == 0
        # 每个头的维度，等于模型维度除以头的总数。
        self.head_dim = args.dim // args.n_heads
        self.n_heads = args.n_heads

        # Wq, Wk, Wv 参数矩阵，每个参数矩阵为 n_embd x dim
        # 这里通过三个组合矩阵来代替了n个参数矩阵的组合，其逻辑在于矩阵内积再拼接其实等同于拼接矩阵再内积，
        # 不理解的读者可以自行模拟一下，每一个线性层其实相当于n个参数矩阵的拼接
        self.wq = nn.Linear(args.n_embd, self.n_heads * self.head_dim, bias=False)
        self.wk = nn.Linear(args.n_embd, self.n_heads * self.head_dim, bias=False)
        self.wv = nn.Linear(args.n_embd, self.n_heads * self.head_dim, bias=False)
        # 输出权重矩阵，维度为 dim x dim（head_dim = dim / n_heads）
        self.wo = nn.Linear(self.n_heads * self.head_dim, args.dim, bias=False)
        # 注意力的 dropout
        self.attn_dropout = nn.Dropout(args.dropout)
        # 残差连接的 dropout
        self.resid_dropout = nn.Dropout(args.dropout)
        self.is_causal = is_causal

        # 创建一个上三角矩阵，用于遮蔽未来信息
        # 注意，因为是多头注意力，Mask 矩阵比之前我们定义的多一个维度
        if is_causal:
            mask = torch.full((1, 1, args.max_seq_len, args.max_seq_len), float("-inf"))
            mask = torch.triu(mask, diagonal=1)
            # 注册为模型的缓冲区
            self.register_buffer("mask", mask)

    def forward(self, q: torch.Tensor, k: torch.Tensor, v: torch.Tensor):

        # 获取批次大小和序列长度，[batch_size, seq_len, dim]
        bsz, seqlen, _ = q.shape

        # 计算查询（Q）、键（K）、值（V）,输入通过参数矩阵层，维度为 (B, T, n_embed) x (n_embed, dim) -> (B, T, dim)
        xq, xk, xv = self.wq(q), self.wk(k), self.wv(v)

        # 将 Q、K、V 拆分成多头，维度为 (B, T, n_head, dim // n_head)，然后交换维度，变成 (B, n_head, T, dim // n_head)
        # 因为在注意力计算中我们是取了后两个维度参与计算
        # 为什么要先按B*T*n_head*C//n_head展开再互换1、2维度而不是直接按注意力输入展开，是因为view的展开方式是直接把输入全部排开，
        # 然后按要求构造，可以发现只有上述操作能够实现我们将每个头对应部分取出来的目标
        xq = xq.view(bsz, seqlen, self.n_heads, self.head_dim)
        xk = xk.view(bsz, seqlen, self.n_heads, self.head_dim)
        xv = xv.view(bsz, seqlen, self.n_heads, self.head_dim)
        xq = xq.transpose(1, 2)
        xk = xk.transpose(1, 2)
        xv = xv.transpose(1, 2)

        # 注意力计算
        # 计算 QK^T / sqrt(d_k)，维度为 (B, nh, T, hs) x (B, nh, hs, T) -> (B, nh, T, T)
        scores = torch.matmul(xq, xk.transpose(2, 3)) / math.sqrt(self.head_dim)
        # 掩码自注意力必须有注意力掩码
        if self.is_causal:
            assert hasattr(self, 'mask')
            # 这里截取到序列长度，因为有些序列可能比 max_seq_len 短
            scores = scores + self.mask[:, :, :seqlen, :seqlen]
        # 计算 softmax，维度为 (B, nh, T, T)
        scores = F.softmax(scores.float(), dim=-1).type_as(xq)
        # 做 Dropout
        scores = self.attn_dropout(scores)
        # V * Score，维度为(B, nh, T, T) x (B, nh, T, hs) -> (B, nh, T, hs)
        output = torch.matmul(scores, xv)

        # 恢复时间维度并合并头。
        # 将多头的结果拼接起来, 先交换维度为 (B, T, n_head, dim // n_head)，再拼接成 (B, T, n_head * dim // n_head)
        # contiguous 函数用于重新开辟一块新内存存储，因为Pytorch设置先transpose再view会报错，
        # 因为view直接基于底层存储得到，然而transpose并不会改变底层存储，因此需要额外存储
        output = output.transpose(1, 2).contiguous().view(bsz, seqlen, -1)

        # 最终投影回残差流。
        output = self.wo(output)
        output = self.resid_dropout(output)
        return output

    为了方便理解维度的变化，我们在脑海里预设一组真实大模型的典型参数：

    • batch_size (批次大小，bsz) = 32
    • seq_len (序列长度，T) = 10
    • n_embd (输入词向量维度) = 512
    • dim (注意力内部总维度) = 512
    • n_heads (头数，nh) = 8
    • head_dim (每个头的维度，hs) = 512 / 8 = 64

    1. 层归一化 (LayerNorm)#

    为什么不使用Batch Norm（批归一化）？

    1). 批归一化缺点#

    批归一化存在一些缺陷，例如：

    • 当显存有限，mini-batch 较小时，Batch Norm 取的样本的均值和方差不能反映全局的统计分布信息，从而导致效果变差；
    • 对于在时间维度展开的 RNN，不同句子的同一分布大概率不同，所以 Batch Norm 的归一化会失去意义；
    • 在训练时，Batch Norm 需要保存每个 step 的统计信息（均值和方差）。在测试时，由于变长句子的特性，测试集可能出现比训练集更长的句子，所以对于后面位置的 step，是没有训练的统计量使用的；
    • 应用 Batch Norm，每个 step 都需要去保存和计算 batch 统计量，耗时又耗力

    把神经网络里的数据想象成一次期末考试的成绩单。

    • Batch（批次）：一个班级里的学生人数（比如 32 个学生）。
    • Sequence Length（序列长度）：每个人考了多少门课（句子长度，比如 10 个词）。
    • Hidden Size（特征维度）：每门课的考卷上有多少道题（比如 512 维特征）。

    Batch Norm 的计算逻辑是： 把这 32 个学生、在第 1 门课的第 1 道题上的分数抽出来，算一个平均分，然后归一化。

    这就直接导致四个致命缺陷：

    1. “样本太少，统计失真”（受限于 Batch Size）： 如果显存很小，一个 Batch 只能塞下 2 个句子（2 个学生）。用 2 个人的分数去代表平均水平，均值和方差会剧烈抖动，导致模型崩溃。

    2. “长短句参差不齐”（序列长度问题）： 句子长度是不一样的。有的学生考了 10 门课，有的学生只考了 3 门课。当 Batch Norm 算到第 10 门课的平均分时，发现 32 个学生里只有 5 个人考了这门课，剩下的人全是 0（Padding 填充符）。这算出来的均值完全失去了统计学意义。

    3. “没见过的超长句子”（测试集的灾难）： 在训练时，Batch Norm 需要记录每一道题的“历史平均分”。如果平时测试大家最多只考 20 门课（最长序列 20），但期末考试突然来了一个考了 50 门课的学生。对于第 21~50 门课，Batch Norm 根本没有历史记录可以用来归一化，当场宕机。

    4. “耗时又耗力”： 在时间维度展开算这么多乱七八糟的全局变量，内存访问极其不连续，拖慢了显卡的计算速度。

    Layer Norm 的逻辑： 只针对某一个句子里的某一个词，把它自己身上的 512 维特征加起来，算出一个均值和方差，进行归一化。

    Layer Norm 的优点：

    1. 不受 Batch Size 影响： 就算只有一个句子、一个词，Layer Norm 依然能完美算出它的均值和方差。
    2. 适应变长序列： 句子长短无所谓，因为归一化是针对“单个词内部”独立进行的，不用管别人长短。
    3. 测试阶段不需要历史统计量： 它在推理（生成）文本时，是实时计算当前词的统计量的，根本不需要像 Batch Norm 那样去保存训练时的滑动平均值。

    class LayerNorm(nn.Module):
    ''' Layer Norm 层'''
    def __init__(self, features, eps=1e-6):
        super().__init__()
        # 线性矩阵做映射
        self.a_2 = nn.Parameter(torch.ones(features))
        self.b_2 = nn.Parameter(torch.zeros(features))
        self.eps = eps
    
    def forward(self, x):
        # 在统计每个样本所有维度的值，求均值和方差
        mean = x.mean(-1, keepdim=True) # mean: [bsz, max_len, 1]
        std = x.std(-1, keepdim=True) # std: [bsz, max_len, 1]
        # 注意这里也在最后一个维度发生了广播
        return self.a_2 * (x - mean) / (std + self.eps) + self.b_2

    1. 为什么非要加这个 xxx？

    为什么不直接输出注意力算出来的结果，非要把原来的 xxx 加回来呢？

    痛点一：信息的遗忘

    如果只保留注意力的结果，模型在经过几十层网络后，词向量在不断地融合上下文，它可能会忘了“自己到底是谁”。

    比如“苹果”，在融合了“吃”之后，可能会变得太像一个动作的受体。

    加上原来的 xxx 后，公式的物理意义变成了：“保持我作为‘苹果’的本意不变，同时加上我吸收到的周围的语境信息。” 原来的特征不会丢失。

    痛点二：“梯度消失”

    在训练模型时，误差（梯度）需要从最后一层一层层往回传（连乘）。

    如果网络有 100 层，很多小于 1 的数字连乘 100 次，梯度就会变成 0.0000001，导致最前面的层根本得不到更新。

    但是有了这个 + x，根据微积分的求导法则，f(x)+xf(x) + xf(x)+x 的导数是 f′(x)+1f'(x) + 1f′(x)+1。 无论注意力的梯度 f′(x)f'(x)f′(x) 变得多小，甚至变成了 0，梯度都可以沿着 + 1 ，无损地直接传回上一层。这使得训练极深的大模型成为了可能。

    1. 第二个公式的意义 output=x+FNN(LayerNorm(x))output = x + \text{FNN}(\text{LayerNorm}(x))output=x+FNN(LayerNorm(x)) 这个公式的逻辑和上面完全一模一样，只是把中间从多头注意力换成前馈神经网络。
    • 注意力机制（Attention） 的作用是：让词和词之间交换信息。
    • 前馈神经网络（FFN） 的作用是：在每个词自己的特征内部进行升维再降维的非线性变换，让特征更丰富。

    在一个 Transformer 的编码器（Encoder）块里，数据就是这样连续：

    先走一次 “注意力+残差” 提取全局关系， 再走一次 “FFN+残差” 丰富自身特征。 这样连续堆叠 32 层，就构成了一个庞大聪明的 LLM。

    1. [EncoderLayer(args) for _ in range(args.n_layer)]

      • 这是 Python 的列表推导式。假设配置文件里写了 args.n_layer = 12，这就意味着模型要造 12 层。
      • 这行代码会连续实例化 12 个 EncoderLayer 对象。
      • 核心重点： 这 12 个层的内部结构（多头注意力 + FFN）是一模一样的，但是它们内部的参数权重矩阵（WQ,WK,WVW^Q, W^K, W^VWQ,WK,WV 等）是完全独立、互不干扰的！第一层负责提取浅层特征（比如词性），第十二层负责提取极其抽象的深层语义。

    2. nn.ModuleList(...)

      • 为什么不直接用 Python 自带的普通的 list，而非要套一层 nn.ModuleList？
      • 这是 PyTorch 的硬性规定。 如果你用普通的 list 把这 12 层装起来，PyTorch 的底层引擎会“看不见”它们，在反向传播更新梯度时，这 12 层里的参数全都会被忽略，模型就废了。
      • 套上 nn.ModuleList，就像是在向 PyTorch 注册：“请把这个列表里的所有网络层都纳入你的计算图，好好计算梯度。”

    3. self.norm = LayerNorm(args.n_embd)

      • 在数据跑完所有的 N 层之后，最后再做一次层归一化（Layer Norm），稳定特征分布，然后送出编码器。

def PositionEncoding(seq_len, d_model, n=10000):
    P = np.zeros((seq_len, d_model))

    class PositionalEncoding(nn.Module):
    '''位置编码模块'''

    def __init__(self, args):
        super(PositionalEncoding, self).__init__()
        # Dropout 层
        # self.dropout = nn.Dropout(p=args.dropout)

        # block size 是序列的最大长度
        pe = torch.zeros(args.block_size, args.n_embd)
        position = torch.arange(0, args.block_size).unsqueeze(1)
        # 计算 theta
        div_term = torch.exp(
            torch.arange(0, args.n_embd, 2) * -(math.log(10000.0) / args.n_embd)
        )
        # 分别计算 sin、cos 结果
        pe[:, 0::2] = torch.sin(position * div_term)
        pe[:, 1::2] = torch.cos(position * div_term)
        pe = pe.unsqueeze(0)
        self.register_buffer("pe", pe)

    def forward(self, x):
        # 将位置编码加到 Embedding 结果上
        x = x + self.pe[:, : x.size(1)].requires_grad_(False)
        return x

            loss = F.cross_entropy(logits.view(-1, logits.size(-1)), targets.view(-1), ignore_index=-1)
        else:
            # 推理阶段，我们只需要 logits，loss 为 None
            # 取 -1 是只取序列中的最后一个作为输出
            logits = self.lm_head(x[:, [-1], :]) # note: using list [-1] to preserve the time dim
            loss = None

        return logits, loss
