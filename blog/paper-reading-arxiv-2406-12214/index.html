    0 comments
    Arxiv ID 2406.12214
    幻觉翻译 2406.12214

    您的高精地图构建器在传感器损坏的情况下是否可靠?（NeurIPS'24）

    本文提出 MapBench，首次系统评测在线高精地图构建在传感器损坏下的可靠性，覆盖 8 个方法族的 31 种配置，以及 8 类相机、8 类 LiDAR 和 13 类多传感器 corruption。实验表明，clean mAP 不能替代鲁棒性评测，多模态融合在模态缺失与联合腐蚀下仍可能显著退化；SwinT backbone、时序融合以及 PhotoMetric、PolarMix 等增强策略可改善部分鲁棒性指标。

    MapBench：您的高精地图构建器在传感器损坏的情况下是否可靠? NeurIPS’24 (CCF-A)

    项目页：MapBench

    1. 研究背景与动机#

    (1) 高精地图是什么？为什么重要？

    HD map（High-Definition Map，高精地图） 高精地图（HD Map） - 自动驾驶指南 是自动驾驶系统的基础组件，提供厘米级的交通规则、向量化拓扑与导航信息，使自车能精确定位并预判前方道路。高精地图构建任务被形式化为：在 BEV（鸟瞰图）视角下，预测一组 向量化静态地图元素（人行横道、车道线、路沿等）。

    (2) 为什么需要评测高精地图构建的鲁棒性？

    • 现有高精地图构建几乎全在理想条件下设计与评测（例如晴天、传感器完整），而真实驾驶中，恶劣天气、运动失真、传感器故障（丢帧、崩溃、回波不全）不可避免。
    • 此前无系统性工作评测高精地图构建在传感器损坏下的可靠性。
    • 已有鲁棒性 benchmark（Robo3D、RoboBEV、RoboDepth），但只覆盖 3D 检测、分割、深度、占用预测,而无对高精地图构建的鲁棒性 benchmark；且 RoboBEV 对多模态融合的传感器失效分析主要停留在整模态缺失，缺少对部分传感器退化、两种模态联合腐蚀以及不同腐蚀强度组合的系统评估。

    2. 核心贡献#

    1. 首次系统提出高精地图构建的鲁棒性基准：MapBench 是首个全面基准化并评估高精地图构建方法在单模态与多模态传感器损坏下可靠性的研究。
    2. 对总共 31 种最先进的高精地图构建方法及其变体在三种配置下进行了广泛基准测试：覆盖 camera-only / LiDAR-only / fusion 三类；按模态分别评测 8 camera + 8 LiDAR + 13 多传感器 corruption，单模态 corruption 各设 3 个严重程度（Easy/Moderate/Hard）。
    3. 识别有效的鲁棒性提升策略：通过消融揭示多模态融合、数据增强、架构技巧（backbone、BEV encoder、temporal fusion、训练 epoch）对鲁棒性的影响。

    3. MapBench 基准详解#

    3.1 Corruption 总数与分类#

    (1) Camera Sensor Corruptions（8 种）#

    采用 8 种来自 RoboBEV 的真实世界摄像头传感器损坏情况,从三个角度进行分析:外部环境、内部传感器以及传感器故障。

    Camera 传感器损坏类型与模拟方式
    分组 Corruption 说明
    外部环境 Bright 强光（HSV 调整）
    Low-Light (Dark) 弱光（scale 0.5/0.4/0.3）
    Fog 雾（thickness, smoothness）
    Snow 雪（多参数）
    内部硬件 Motion Blur 运动模糊（radius, sigma）
    Color Quantization (Quant) 颜色量化（bit 5/4/3）
    传感器故障 Camera Crash 持续丢某些视角（drop 2/4/5 相机）
    Frame Lost 随机丢帧（概率 2/6、4/6、5/6）

    (2) LiDAR Sensor Corruptions（8 种）#

    引入了来自Robo3D的 8LiDAR 传感器损坏情况，这些场景在真实世界部署中具有较高的发生概率。这些损坏涵盖了外部、内部以及传感器故障等多种情形。

    LiDAR 传感器损坏类型与模拟方式
    分组 Corruption 说明
    外部环境 Fog 雾导致后向散射与衰减（beta）
    Wet Ground 湿地面，回波衰减
    Snow 雪（snowfall rate, terminal velocity）
    内部硬件 Motion Blur 车辆运动致点云模糊
    Beam Missing 灰尘/昆虫致部分 beam 丢失（drop 8/16/24）
    传感器故障 Crosstalk 多传感器光脉冲干扰
    Incomplete Echo 部分回波不完整
    Cross-Sensor 跨设备/配置 LiDAR（domain gap）

    (3) Multi-Sensor Corruptions（13 种）#

    为了探究相机-LiDAR 融合模型的鲁棒性，论文设计了 13 种相机-LiDAR 损坏组合，这些组合基于前述的传感器故障类型，分别或同时对相机和 LiDAR 输入进行扰动。这些多传感器损坏被分为仅相机损坏、仅 LiDAR 损坏以及两者的组合，涵盖了大多数真实世界场景。

    • 3 种 camera-only（LiDAR 干净）：使用“干净”的 LiDAR 点云数据和三种相机故障情况，如相机不可用(所有 RGB 图像的像素值均设为零)、相机崩溃和帧丢失。
    • 4 种 LiDAR-only（camera 干净）：使用“干净”的相机数据和损坏的 LiDAR 数据作为输入，设计了 4 种仅 LiDAR 损坏的情况。包括完整的 LiDAR 故障(由于当所有点都缺失时没有任何模型能正常工作，论文通过仅保留一个点作为输入来近似此场景)、不完整回波、串扰和跨传感器干扰。
    • 6 种 camera-LiDAR 组合（Figure 4）：Camera Crash 或 Frame Lost 分别与 Incomplete Echo、Crosstalk、Cross-Sensor 组合；附录 B.3 另列了双模态不可用、Low-Light+Cross-Sensor、双 Motion Blur、双 Fog 等组合，与实际实验表不一致

    3.2 如何模拟 corruption#

    • 对 nuScenes val 集施加 corruption（算法模拟，不重新采集）。
    • 每种 corruption 按物理或几何特性设计参数化函数，设 Easy/Moderate/Hard 三档。
    • LiDAR 完全缺失时模型无法工作，故”Unavailable LiDAR”近似为只保留 1 个点。

    4. HD 地图构建任务基础#

    4.1 任务定义#

    • 输入：多视角相机图像（nuScenes 6 路）和/或 LiDAR 点云。
    • 输出：BEV 视角下的一组向量化地图元素，用有序点序列或曲线参数表示。
    • 本质：在线端到端预测车辆周围（如 30m×60m）的静态地图要素，供下游规划或者定位用。

    HDMapNet 的在线端到端预测 Demo：

    4.2 向量化地图元素#

    论文关注 3 类向量化地图元素（与 nuScenes 协议一致）：

    • pedestrian crossing（人行横道，ped.）
    • divider（车道分隔线，div.）
    • boundary（道路边界/路沿，bou.）

    “向量化”是相对”栅格化（rasterized）“而言：直接预测点序列或曲线参数，而非像素级语义图。代表性表示：

    • point-based：PivotNet（pivot point）、MapTR/MapTRv2（point set + polyline）
    • line/curve-based：BeMapNet（分段 Bezier 曲线）
    • hybrid：HIMap（点+线混合）

    栅格化地图示例：

    4.3 三类方法区别#

    • Camera-only：多视角 RGB -> BEV encoder（LSS/Deformable Attention/GKT/BEVPool/BEVFormer）投射到 BEV。语义丰富但缺深度。
    • LiDAR-only：点云 -> PointPillars/SECOND。精确几何但稀疏。
    • Camera-LiDAR fusion：融合两模态，分 point/feature/BEV-level。BEV-level 最强（如 HIMap、MapTR C&L）。论文中发现一般 camera > LiDAR-only，fusion 最优。

    4.4 评价指标#

    MapBench 先使用向量化高精地图构建的标准精度指标 mAP，再以 mAP 为基础定义两组鲁棒性指标：

    • CE / mCE：将候选模型在腐蚀数据上的错误与基线模型比较；
    • RR / mRR：将候选模型在腐蚀数据上的精度与它自身的 clean 精度比较。

    (1) mAP：基础任务精度

    论文评测以下三类向量化地图元素：

    所以 RR 和 mRR 越大越好。RR 不使用另一个模型作为 baseline，而是使用当前候选模型自己的 mAPcleanmAP_{\mathrm{clean}}mAPclean​ 作为分母。如果某种 corruption 下的平均 mAP 偶然高于 clean mAP，RRiRR_iRRi​ 可以大于 1，表格值也可以超过 100。

    mRR 衡量的是相对精度保留率，而不是腐蚀条件下的绝对精度。clean mAP 较低的模型因为分母较小，可能得到较高的 mRR，但其腐蚀后的绝对 mAP 仍然不高。

    (4) 三类指标应该怎样结合

    指标比较对象回答的问题方向
    mAP模型预测与真实地图标注模型的绝对任务精度是多少越大越好
    mCE候选模型与指定 baseline候选模型的腐蚀错误相对 baseline 有多大越小越好
    mRR候选模型腐蚀精度与其自身 clean 精度模型保留了多少自身正常性能越大越好

    实际计算顺序是：先得到候选模型的 clean mAP；再计算它在每类 corruption 的 Easy、Moderate、Hard 三档 mAP；然后分别计算每一类的 CEiCE_iCEi​ 和 RRiRR_iRRi​；最后跨 corruption 类型求平均，得到 mCE 和 mRR。

    5.2 整体退化程度#

    • Camera-only：Table 1 代表配置的 mRR 普遍仅 40%~60%，其中 HIMap 为 56.6%；若计入 Table 15 的全部变体，BeMapNet-SwinT（30 ep）达到 57.9%。
    • Fusion：HIMap(C&L) clean mAP 高达 74.3，但 mRR 仅 41.7、mCE 高达 110.6！

    本文在两个 fusion 模型上的观察：HIMap clean 优于 MapTR，但相对指标 mRR/mCE 更差。该结果提示 clean 精度与相对鲁棒性并不等价，但不足以证明所有模型都存在”性能越高、鲁棒性越差”的普遍规律。

    5.3 哪些 corruption 最致命？#

    Camera-only：

    • Snow 最致命：HIMap 65.5 -> 5.1；MapTR 50.3 -> 3.8；StreamMapNet 63.4 -> 9.1（雪覆盖路面使要素不可识别）。
    • Frame Lost 与 Camera Crash 次之：HIMap Camera Crash 19.4、Frame Lost 19.0。
    • 相对温和：Bright、Color Quant、Motion Blur。

    LiDAR-only：

    • Snow 与 Cross-Sensor 通常最致命
      • MapTR-L Cross-Sensor：33.4 -> 6.4；HIMap-L：44.3 -> 10.8。
    • Incomplete Echo 影响最小（RR ~96-99%，因主要影响深色物体/车辆，而 HD map 关注静态路面）。

    Fusion：

    • Camera 完全缺失：MapTR 62.5->22.5，下降 40.0 个 mAP 点；HIMap 74.3->5.4
    • LiDAR 完全缺失：MapTR 62.5->20.4、HIMap 74.3->32.8，分别下降 42.1 和 41.5 个 mAP 点，而非相对百分比。
    • 在两个 fusion 模型及已测组合中，Cross-Sensor 始终是 Incomplete Echo、Crosstalk、Cross-Sensor 三者中最致命的一类。
    • Frame Lost 总体上比 Camera Crash 更致命；HIMap 与 Cross-Sensor 组合时二者为 14.4 和 14.3。

    Camera、LiDAR 和 Fusion 的鲁棒性对比

    • clean：fusion > camera > LiDAR-only。
    • corruption 下：fusion 可在部分单模态腐蚀中利用另一模态补偿，但在某模态完全缺失时并不必然优于存活模态的单模态模型；例如 MapTR camera-missing 为 22.5，低于 LiDAR-only 的 33.4。HIMap 的 fusion mRR 仅 41.7，但该相对指标也受其较高 clean mAP 分母影响。
    • 单模态中，LiDAR-only mRR（55-63%）整体略高于 camera-only（40-60%），但绝对精度更低。

    6. 提升鲁棒性的策略#

    6.1 多模态融合#

    fusion 可在部分单模态 corruption 中利用互补信息，但并不保证始终优于对应单模态模型；对”双模态同时 corruption”或”某模态完全缺失”仍需专门设计鲁棒融合架构。

    6.2 架构技巧#

    (a) 更大的预训练 backbone（Table 4）：SwinT 显著提升鲁棒性。

    • PivotNet：mCE 100.0 -> 77.8（+22.2）
    • BeMapNet：mCE 100.0 -> 75.9（+24.1）

    (b) BEV encoder 选择（Table 2）：

    • BEVPool、BEVFormer 与 GKT 的 mRR/mCE 差距较小，GKT 取得最低 mCE（97.2）。

    (c) Temporal fusion（Table 3）：

    • StreamMapNet 加 temporal fusion：mRR 增加 8.4 个点（47.1->55.5），mCE 降低 14.1 个点（100.0->85.9），时序信息提供互补线索。

    (d) 训练 epoch（Table 5）：

    • MapTR 24->110 ep：clean mAP 50.3->58.7，mCE 降低 19.1 个点（100.0->80.9），但 mRR 均为 49.3。更长训练提高了绝对精度和 mCE，不代表相对精度保留率同步提高。

    6.3 数据增强#

    Camera-based：

    • PhotoMetric 最有效：mRR 增加 8.2 个点，mCE 降低 15.5 个点（因与 Bright/Low-Light 等 corruption 作用类似）。
    • Rotate / Flip 反而削弱鲁棒性（mCE 升至 105.1/102.5）—几何增强对 HD map 鲁棒性不一定有益。

    LiDAR-based：

    • 所有 LiDAR 增强均有效：PolarMix 的 clean mAP 和 mCE 最佳（+3.0 和 -6.5 个点），但 RTS-LiDAR 的 mRR 最高（57.0 vs. PolarMix 55.2）。

    7. 局限性与启示#

    局限

    1. Corruption 覆盖不全。
    2. 模拟和真实数据有差距，且模型与数据集多样性有限（仅 nuScenes）。
    3. 时序与空间一致性：主要单帧施加 corruption，连续恶劣条件下时空一致性评测仍是开放问题。
    4. 计算资源需求高，但不同模态模型只评测对应的 8/8/13 类 corruption，并非每个模型都执行完整评测。

    启示

    • 高精度 ≠ 必然高鲁棒性：两个 fusion 模型中，HIMap(C&L) clean 更高但相对鲁棒指标更差。
    • Fusion 模型需专门设计缺失模态鲁棒性：被测现有方法通常假设传感器完整；某模态完全缺失时性能会显著下降，且不一定优于存活模态的单模态模型。
    • 可参考的策略：SwinT backbone、temporal fusion、长训练、PolarMix/PhotoMetric 增强改善了部分绝对或相对指标。
    • 未来方向：corruption-aware 训练、缺失模态鲁棒融合架构、真实恶劣数据采集、时空一致多帧 corruption 模拟。

    MapBench 首次系统提出高精地图构建的鲁棒性基准，按 camera、LiDAR 和 fusion 模态分别用三类 29 种 corruption 情景评测 8 个方法族的 31 个变体。两个 fusion 模型中，HIMap clean mAP 高于 MapTR，但相对鲁棒指标更差，说明 clean 精度不能替代鲁棒性评测；SwinT backbone、temporal fusion、长训练及 PolarMix 或 PhotoMetric 等在部分指标上有效。它把鲁棒性问题从 3D 检测等领域扩展到高清地图。
